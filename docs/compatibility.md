# KonomiTV・Komorebi互換状況

この表は、Sazanami DVRで実際に使える操作と、まだ使えない操作を示します。確認対象はKonomiTV v0.14.1とKomorebi 1.1.0-beta6です。

「自動確認」は、合成データを使うテストが通っている状態です。「実環境確認」では、KonomiTVとMirakurunを使った一連の操作まで試しています。コマンドが応答するだけでは不十分です。

## KonomiTVの基本的な録画操作は使える

| 操作 | CtrlCmd | 状態 | 確認範囲 |
|---|---:|---|---|
| バックエンドの起動確認 | 2200 | 実環境確認済み | KonomiTV起動時の接続確認 |
| チャンネル設定の取得 | 1060 | 実環境確認済み | `ChSet5.txt`相当の固定スナップショット |
| サービス一覧の取得 | 1021 | 実環境確認済み | 保存済み番組表と同じ世代の一覧 |
| 番組表の取得 | 1029 | 実環境確認済み | KonomiTV v0.14.1が使う全サービス指定 |
| 番組検索 | 1025 | 自動確認済み | キーワード、除外語、正規表現、番組名限定、放送局、日時、番組長、無料・有料。ジャンルとあいまい検索は未対応 |
| 録画中の番組表更新 | ― | 実環境確認済み | 起動直後と一定間隔。録画中の更新後も、録画完了と再生開始を確認 |
| 予約一覧の取得 | 2011 | 実環境確認済み | 未完了予約と録画中表示 |

| 自動予約条件の一覧・追加・変更・削除 | 2131、2132、2134、1033 | 実環境確認済み | KonomiTV v0.14.1のHTTP APIから4操作を実行。実Mirakurunの番組表からの予約作成と、再起動後の重複防止を確認 |

| ライブ視聴の開始・中継・終了 | 1073、301、1074 | 実環境確認済み | KonomiTV v0.14.1のライブAPIが25秒間HTTP 200を維持。直接接続の2本同時と20回の繰り返しも成功 |
| 録画開始前の番組時刻追従 | 予約・録画機能 | 自動確認済み | 同じMirakurun内の同じ番組で、固定上限内の開始・終了変更だけを反映。実放送の変更は未観測 |
| 録画中の終了時刻延長 | 予約・録画機能 | 自動確認済み | 同じ番組で開始時刻が変わらない延長だけを反映。実放送の延長は未観測 |
| 録画中の再接続 | 録画機能 | 実環境確認済み | 一時的な切断で最大3回。欠損の補完はしない |
| 複数同時録画 | 予約・録画機能 | 実環境確認済み | 既定1件、明示上限1～8件。4台のチューナーを持つMirakurunで、異なる2局を別stream、DB行、録画ファイルへ分離 |

番組表の表示、予約、録画、完成したTSファイルの検出と再生開始は、v0.0.1で一件確認しました。v0.0.2では、既定プリセットから予約した一件が完了し、録画済み一覧へ加わることを確認しました。v0.0.7では、異なる2局を約5分間同時に録画し、別々の完成ファイルとDB状態を再起動後に読み出せることを確認しました。v0.0.8では、隔離DBを使い、自動予約条件の4操作、予約作成、再起動後の重複防止を確認しました。長時間運転と、すべての録画設定は未確認です。

## 自動予約は層ごとに確認状況が異なる

| 対象 | 状態 | 確認したこと |
|---|---|---|
| KonomiTV v0.14.1のHTTP API | 実環境確認済み | 条件の一覧、追加、変更、削除 |
| KonomiTV v0.14.1の同梱画面 | 操作なし | HTTP APIはあるが、同梱画面から条件を編集する導線は確認できない |
| Komorebi 1.1.0-beta6 | ソース確認済み、実環境未確認 | 一覧、追加、削除を送信する。変更はクライアント内で送信前に失敗する |
| Sazanami DVRの保存 | 実環境確認済み | 条件の全項目をSQLiteへ保存し、再起動後に読み出す |
| Sazanami DVRの評価 | 実環境確認済み | 実番組表から通常予約を作り、再起動後の再評価で重複させない |

## KonomiTVでまだ使えない操作がある

| 操作 | CtrlCmd | 現在の扱い |
|---|---:|---|
| 局ロゴの取得 | 2060 | 未対応。2060のロゴ用ファイル名は拒否する |
| 自動予約の高度な検索・録画設定 | 2131、2132、2134、1033 | 条件は失わず保存・返却するが、未対応設定を含む条件から予約は作らない |
| チューナー予約・動作一覧 | 1016、1066 | 未対応。1033はチューナー一覧ではなく、自動予約条件の削除として対応 |
| 録画開始後の短縮・開始時刻変更 | 予約・録画機能 | 未対応。録画中は終了時刻の延長だけに対応 |

KonomiTVが送る録画設定のうち、録画モード、優先度、番組追従、余白などには現在の制限があります。設定画面に項目が表示されても、未対応の組み合わせは失敗応答になります。

自動予約で現在実行できるのは、キーワードと除外語、正規表現、大文字と小文字の区別、番組名だけの検索、サービス、曜日と時刻、番組時間、有料・無料の指定です。録画設定はSazanami DVRが受け付ける初版の組み合わせに限ります。ジャンル、類似検索、映像・音声種別、録画済み番組名との照合、録画後処理、保存先指定などを含む条件は一覧へ残しますが、誤った予約を避けるため評価対象から外します。

## Komorebiの録画一覧・直接再生・直接ライブは自動確認済み

Android TV向けKomorebiは、KonomiTV経由の接続とEDCB直接接続の両方をv1.0の対象として調査しています。v0.0.9では、EDCB直接接続版が使う録画済み一覧、詳細、元のTSの直接再生を実装しました。

| 操作 | 接続 | 状態 | 確認範囲 |
|---|---|---|---|
| 完成録画の一覧 | CtrlCmd 2017 | 自動確認済み | 最大16,384件。DBは256件ずつ読み、全件を一度にメモリへ載せない |
| 完成録画の詳細 | CtrlCmd 2024 | 自動確認済み | 完成条件を満たす一件だけを返す |
| 再生URLの取得 | HTTP resolver | 自動確認済み | 絶対パスを含まない仮想URLだけを返す |
| 元のTSの直接再生とシーク | HTTP GET／HEAD／Range | 自動確認済み | 同時8件まで。完成状態、権限、所有者、サイズを再確認 |
| 代替画像、空チャプター、最小タイル情報 | HTTP | 自動確認済み | 一覧を壊さないための最小応答。実サムネイルではない |
| LANからの直接接続 | CtrlCmd／HTTP | 自動確認済み | 既定は端末内。private IPまたは全インターフェースを明示可能 |
| 直接ライブの開始・中継・終了 | CtrlCmd 1073、301、1074 | 実通信確認済み | 固定版と同じ要求で1本、2本同時、20回の繰り返しを実Mirakurunへ接続。Android TV画面は未確認 |
| Android TVでの一覧、詳細、再生、シーク | Komorebi 1.1.0-beta6 | 実環境未確認 | クライアントを固定版で導入してから確認する |
| Android TVでの主画面・二画面ライブ | Komorebi 1.1.0-beta6 | 実環境未確認 | クライアントを固定版で導入してから確認する |
| 画質変換、キャスト | HTTP | 未対応 | 後続版で操作ごとに追加する |

Sazanamiへ要求が届かないクライアント側の制限は、再現条件と代替手段を確認できた場合だけ「実現できない操作」として区別します。

## 対応済みの表示は実環境確認後に更新する

新しい操作は、通信形式の自動テスト、既存機能の回帰テスト、対象クライアントでの実環境確認がそろってから「対応済み」へ変更します。未確認のKonomiTV全体、Komorebi全体、EDCB全体への互換性は表明しません。

不具合を報告する場合は、家庭内のIPアドレス、ホスト名、番組情報、TS内容を除いた再現手順とSazanami DVRのバージョンを添えてください。脆弱性は公開Issueへ書かず、[セキュリティポリシー](../SECURITY.md)に従ってください。
