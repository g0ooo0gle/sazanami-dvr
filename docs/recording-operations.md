# 録画機能の運用手順

この文書では、KonomiTVから受け取った予約をMirakurunの放送ストリームから録画する手順を説明します。
同時録画は既定で一件です。Mirakurunと保存先の能力を確認した場合だけ、1～8件の範囲で明示できます。常駐サービスの自動登録は行いません。

## 起動前に確認すること

次の準備が必要です。

- `db migrate`が完了し、DBが最新形式になっている
- `catalog sync`が成功し、現在の番組情報が保存されている
- `channel-map`が保存済みカタログと一致し、TSIDを含んでいる
- `data-root`と`recording-root`を、実行ユーザーだけが読み書きできる
- MirakurunまたはmirakcのURLが分かっている
- KonomiTVとSazanami DVRが同じPC上で動くか、クライアントから宅内LANで接続できる

初回は、データ保存先と録画保存先を別のディレクトリにすることを勧めます。

```text
mkdir -m 700 <data-root>
mkdir -m 700 <recording-root>
```

チャンネル設定の形式と確認方法は
[CtrlCmdチャンネル待受の使い方](ctrlcmd-channel-runtime.md)を参照してください。

## 起動する

次のコマンドを実行します。

```text
sazanami-dvr recording serve \
  --data-root <data-root> \
  --recording-root <recording-root> \
  --channel-map <channel-map> \
  --provider mirakurun \
  --base-url <mirakurun-url> \
  --http-listen 127.0.0.1:40773
```

起動時は、次の順に確認します。

1. DBの形式と単独所有
2. 録画保存先の権限と単独所有
3. チャンネル設定と現在のカタログ
4. 前回終了時に残った録画処理
5. CtrlCmdと録画履歴HTTPの待受
6. 録画プロセス内の番組表更新

待受開始後、Mirakurunの版、サービス、番組を直ちに確認します。録画streamは余白を反映した予定開始時刻に、ライブstreamはクライアントから301を受けた場合だけ開きます。

CtrlCmdは既定でIPv4の全interfaceに待ち受けます。Android TVなど別の端末から録画ファイルも直接再生する場合だけ、HTTPもLANで待ち受けます。

```text
sazanami-dvr recording serve \
  <ほかの引数> \
  --http-listen 0.0.0.0:40773
```

この接続口には認証とTLSがありません。信頼できる宅内LANだけで使い、インターネットへ直接公開しないでください。起動ログには実際のIPを出さず、端末内待受かLAN待受かだけを表示します。

## 録画履歴と完成録画を読む

録画履歴は、新しい録画から100件まで取得できます。成功だけでなく、失敗、途中終了、中止、開始できなかった結果も含みます。続きを読む場合は、直前の応答にある`next_before`を`before`へ指定します。

```text
GET /api/recordings?limit=50
GET /api/recordings/<録画番号>
```

完成録画は`/recordings/<録画番号>.ts`から読み出せます。全体取得、HEAD、単一のRange要求に対応し、同時配信は8件までです。DBに記録した完成状態、ファイルの種類、権限、所有者、サイズを開くたびに確認します。絶対パスや保存先の相対パスはAPIへ返しません。

Komorebi 1.1.0-beta6向けには、CtrlCmd 2017で一覧、2024で詳細を返します。resolverが返す仮想URLから元のTSを直接再生します。画像は中立な代替画像、チャプターは空、タイル情報は最小値です。実サムネイルや画質変換にはまだ対応していません。

## 局ロゴを使う

KonomiTVはCtrlCmd 2060、Komorebiは`/legacy/logo.lua`から局ロゴを取得します。Sazanami DVRは、完成済み番組表で放送局を一つに絞れた場合だけ、Mirakurunの局ロゴをその場で取得して返します。ロゴはDBやファイルへ保存しません。

ロゴ一件は2 MiB、取得は5秒、同時取得は4件までです。ロゴがない場合や取得に失敗した場合、クライアントは標準画像を表示します。番組表、予約、録画、ライブ視聴には影響しません。Komorebiを別端末から直接つなぐ場合は、録画再生と同じ`--http-listen`を信頼できる宅内LANへ明示してください。

## ライブ視聴を使う

KonomiTV v0.14.1とKomorebi 1.1.0-beta6の直接接続は、CtrlCmd 1073で放送局を選び、301の同じ接続でMirakurunのMPEG-TSを受け取ります。終了時は1074を送ります。Sazanami DVRが直接チューナーを制御することはありません。

Komorebiでは、接続設定の「優先ソース」で`EDCB (ダイレクトストリーミング)`を選びます。
初期値の動画変換経路はSazanami DVRでは使えません。詳しくは[Komorebi接続手順](komorebi-setup.md)を
参照してください。

ライブ視聴は同時4本までです。チャンネル選択後30秒以内に受信を始めない利用は破棄します。一接続は12時間、提供元とクライアントの受信停止は10秒を上限として終了します。録画用とライブ用の接続枠は分かれているため、ライブ4本がSazanami DVRの録画上限を減らすことはありません。ただし、Mirakurun側のチューナー数と優先度は別に制約を受けます。

ライブ利用はDBへ保存しません。Sazanami DVRの停止、クライアント切断、Mirakurun切断、1074のいずれでも接続と利用枠を解放します。再起動後はクライアントが新しく開始します。

## 番組表を更新する

番組表は起動直後と、直前の更新終了から既定5分後に更新します。同時に二回は実行しません。更新間隔を変える場合は、5分から24時間の範囲で指定します。

```text
sazanami-dvr recording serve \
  <ほかの引数> \
  --catalog-refresh-interval 30m
```

一回の更新期限は10分です。取得や保存に失敗した場合は、直前に正常終了した番組表を使い続けます。失敗直後の追加再試行は行わず、次の予定時刻まで待ちます。

新しい番組表は、チャンネル設定との照合に成功した後だけ公開します。一つの番組表要求や予約追加の途中で、新旧の番組表を混ぜません。更新結果には成功・失敗、件数、所要時間、決められた失敗理由だけを出し、接続先や番組情報は出しません。

## 自動予約を使う

自動予約条件はKonomiTVまたはKomorebiから追加し、SQLiteへ保存します。`recording serve`は番組表の更新が成功した後に、完成した一世代の番組表と条件を照合します。条件の追加だけではMirakurunへ接続せず、録画ストリームも開きません。

予約を作れる条件は次のとおりです。

- キーワードと除外語。空白で区切った複数の語はすべて一致した場合に限る
- 正規表現、大文字と小文字の区別、番組名だけを対象にする指定、番組詳細
- ジャンルと除外、あいまい検索、映像・音声種別
- サービス、曜日と時刻、番組時間、有料・無料の指定
- 録画済み番組名の完全一致。同じチャンネルまたは全チャンネルと、確認する日数を指定できる
- 有効・無効、優先度、番組追従、既定または個別の前後余白
- 録画保存ルート内の相対フォルダーと、対応済みのファイル名テンプレート
- 字幕・データ放送の選択と、「デフォルト」「何もしない」の録画後動作
- 許可ディレクトリ内の録画後スクリプト

録画済み番組名の照合では、指定期間内に完全に同じ番組名の録画履歴があると、予約を削除せず無効状態で残します。既に作られた自動予約も、録画開始前なら次の番組表更新で無効へ変えます。録画履歴は256件ずつ、最大16,384件まで一回だけ読みます。履歴を読めない場合は条件を無視せず、その回の自動予約評価を失敗させます。

録画後の電源操作、強制チューナー、ワンセグ別出力はまだ予約作成に使いません。これらを含む条件は削除せず、一覧と変更の応答にはそのまま返します。番組表の更新ログに`unavailable_rules`として件数を出しますが、検索語や番組名は出しません。

一回の評価は、自動予約条件128件、今後8日間の番組32,768件、照合4,194,304回、新しい予約256件までです。上限を超えた番組表では、事前確認の段階で止まり、その回は予約を一件も作りません。作成上限へ達した場合は、その時点までに作った予約を残し、次回の更新で続きを評価します。

同じ番組について、通常予約、自動予約、取消し済み、録画済みのいずれかの履歴がある場合は、別の条件に一致しても新しい予約を作りません。条件を変更または削除しても、すでに作った通常予約は維持します。

自動予約の評価だけに失敗した場合も、正常に取得できた番組表と既存の録画処理は維持します。次の定期更新で再び評価します。短い間隔の自動再試行は行いません。

## 録画時の動き

KonomiTVから予約を受け取ると、番組とサービスの情報を予約時点で固定してDBへ保存します。成功応答は、
DBへの保存が完了した後にだけ返します。

予約の余白を反映した予定開始時刻になると、次の処理を一回だけ実行します。既定余白は開始5秒、終了2秒です。個別余白は前後それぞれ-3,600～3,600秒で指定できます。

1. DBで予約の実行権を取得する
2. `.ts.partial`ファイルを新規作成する
3. Mirakurunの対象サービスストリームを開く
4. 必要な予約だけ字幕・データ放送を上限付きで選別し、固定サイズのバッファでファイルへ書く
5. 5秒以内ごとに進捗と利用者からの停止要求を確認する
6. 一時的な切断では古い接続を閉じ、上限内で同じストリームを開き直す
7. 予定終了時刻または利用者停止でストリームを閉じる
8. ファイルを同期し、既存ファイルを上書きせず`.ts`として公開する
9. DBへ正常完了または利用者停止の結果を保存する
10. 許可済みの録画後スクリプトがあれば、上限時間内で一度だけ実行する

追従ありの予約では、番組表更新で同じ番組の延長を確認すると、予約と録画処理の終了時刻をDBで一緒に延ばします。終了余白は一度だけ加えます。録画処理は5秒ごとの進捗保存で新しい終了時刻を読みます。開始時刻の変更、短縮、別番組への切替えは録画中に反映しません。

## 録画後スクリプト

既定では`<data-root>/post-recording-scripts`内の実行可能ファイルだけを使えます。別の所有者専用ディレクトリを使う場合は、`recording serve`へ`--post-recording-script-root <absolute-path>`を指定します。予約保存時と実行直前に、許可範囲、symlink、ファイル種別、実行権限を確認します。

スクリプトはshellを介さず、引数なしで実行します。最大実行時間は5分です。標準入出力は閉じるか破棄し、親processの環境変数は引き継ぎません。録画番号、完成ファイルの絶対path、終了状態、終了理由だけを固定名の環境変数で渡します。

対象は正常終了した録画と、利用者が停止して完成名へ公開できた部分録画です。開始前停止、録画失敗、再起動時の復旧では実行しません。スクリプトの起動失敗、非0終了、timeout、Sazanami DVRの停止が起きても、完成ファイルと録画結果は変更しません。自動再試行も行いません。

## 基本録画設定を変更する

録画開始前なら、KonomiTVから次の設定をまとめて変更できます。

- 予約を有効または無効にする
- 優先度を1～5にする
- 番組追従を有効または無効にする
- 既定余白を使うか、開始・終了の余白を個別に指定する

無効予約は一覧と重複確認には残りますが、ストリームを開かず、ファイルも作りません。予定終了前なら再び有効にできます。予定終了を過ぎると`DISABLED_EXPIRED`で終了します。

開始可能な予約が複数ある場合は、優先度が高い予約を先に選びます。同じ優先度なら予定開始が早い順、さらに同じなら内部ID順です。すでに録画中の番組を、別の高優先度予約のために停止することはありません。

## 字幕とデータ放送を選ぶ

KonomiTVでは、予約ごとに字幕とデータ放送を「既定に従う」「含める」「含めない」から選べます。Sazanami DVRの既定は、字幕あり、データ放送なしです。自動予約から作る予約にも同じ選択を引き継ぎます。

字幕とデータ放送を両方含める場合は、Mirakurunから受け取ったTSをそのまま保存します。どちらかを除く場合は、最初のPATとPMTを最大1 MiBまで確認し、PMTの字幕またはデータ放送の項目と対応PIDを除きます。TS全体をメモリへ読み込むことはありません。

PATやPMTが壊れている、対象サービスを一つに特定できない、固定上限を超えるなど、安全に選別できない場合は`STREAM_FORMAT_INVALID`で録画を終了します。選択を無視して別の内容を保存したり、自動で両方を含める設定へ変えたりはしません。

録画先とファイル名を指定しない場合、録画ファイルは次の形で作成します。

```text
<recording-root>/YYYY/MM/<録画ID>.ts
```

## 録画先とファイル名を指定する

KonomiTVの録画先欄には、`--recording-root`から見た相対フォルダーを指定できます。たとえば`ドラマ/新作`は`<recording-root>/ドラマ/新作`です。空欄なら番組開始UTCの`YYYY/MM`を使います。絶対パス、`..`、Windowsドライブ、共有パス、逆向きの区切りは使えません。

ファイル名テンプレートでは次のマクロを使えます。時刻は日本時間で展開します。

| 分類 | マクロ |
|---|---|
| 番組 | `$Title$`、`$Title2$`、`$ServiceName$` |
| 開始日時 | `$SDYYYY$`、`$SDYY$`、`$SDMM$`、`$SDM$`、`$SDDD$`、`$SDD$`、`$SDW$`、`$STHH$`、`$STH$`、`$STMM$`、`$STM$`、`$STSS$`、`$STS$` |
| 終了日時 | `$EDYYYY$`、`$EDYY$`、`$EDMM$`、`$EDM$`、`$EDDD$`、`$EDD$`、`$EDW$`、`$ETHH$`、`$ETH$`、`$ETMM$`、`$ETM$`、`$ETSS$`、`$ETS$` |
| 放送時間 | `$DUHH$`、`$DUH$`、`$DUMM$`、`$DUM$`、`$DUSS$`、`$DUS$` |
| 放送ID | `$ONID10$`、`$TSID10$`、`$SID10$`、`$EID10$`、`$ONID16$`、`$TSID16$`、`$SID16$`、`$EID16$` |
| 予約 | `$ReserveID$` |

たとえば`$SDYYYY$-$SDMM$-$SDDD$_$STHH$$STMM$_$Title$`は、日付、開始時刻、番組名を含む`.ts`ファイルになります。末尾に`.ts`がなければ自動で付けます。番組名と放送局名のファイル名に使えない文字は`_`へ置き換えます。展開後の名前が240バイトを超える場合は予約を失敗させ、切り詰めや上書きは行いません。

対応していないマクロ関数、ジャンル、サブタイトル、外部プラグインは使えません。同じ名前の部分ファイルまたは完成ファイルがある場合も上書きせず、その録画だけを失敗として記録します。

## 複数の番組を同時に録画する

複数のストリームを同時に提供できる環境では、起動時に上限を指定します。

```text
sazanami-dvr recording serve \
  <ほかの引数> \
  --max-concurrent-recordings 2
```

指定できる値は1～8で、既定値は1です。Sazanami DVRはチューナー数を推測しません。各録画は別のDB行、ストリーム接続、部分ファイル、再接続回数を使います。一件の録画失敗をDBへ確定できた場合、ほかの録画は続行します。

開始時刻に上限を使い切っている予約は、`RECORDING_SLOT_UNAVAILABLE`として未実行になります。待ち行列へ積んだり、進行中の録画を優先度で中断したりはしません。Mirakurunが接続を拒否した場合は、その録画だけをストリーム取得失敗として記録します。

## 停止する

起動したプロセスへ`SIGINT`または`SIGTERM`を送ります。新しい予約の取得を止め、録画中の全ストリームを中断します。終了結果と部分ファイルを確定するため、最大30秒待ちます。

```text
kill -TERM <pid>
```

強制終了は、部分ファイルとDBの照合を次回起動へ持ち越す可能性があります。通常は`SIGKILL`を使わないで
ください。

## 予約を変更・取り消す

KonomiTVから、録画開始前の予約について有効状態、優先度、番組追従、前後余白を変更できます。番組とチャンネルは変更しません。録画処理が始まった後の変更は失敗します。

録画開始前の予約はKonomiTVから取り消せます。Sazanami DVRは取消し理由と予約番号をDBへ残し、予約行を削除しません。

録画が始まった後にKonomiTVから同じ取消し操作を行うと、停止要求をDBへ保存してから、その録画だけを止めます。同じ停止要求の再送は成功します。188バイト以上を保存できていれば、途中までの内容を通常の`.ts`名で公開します。DBには`PARTIAL/USER_REQUESTED_STOP`として残るため、予定終了した録画とは区別できます。188バイト未満なら完成名を公開しません。すでに完成処理へ入った録画と終了済みの予約は停止できません。

## 番組時刻の変更へ追従する

KonomiTVから番組追従ありで作った予約は、定期的な番組表更新の後に開始時刻と放送時間を見直します。次の条件を全て満たす場合だけ、録画開始前の予約を更新します。

- 同じMirakurun設定、サービス、番組番号である
- 前回の観測から36時間以内である
- 開始時刻の差が前後6時間以内である
- 放送時間が60秒以上12時間以内で、差が6時間以内である
- 録画処理がまだ作られていない

条件を満たさない場合は、予約時の開始・終了時刻を維持します。番組名の類似だけでは更新しません。録画開始後は、開始時刻が同じ番組の終了時刻延長だけを反映します。番組表の更新だけを理由にした短縮、開始時刻変更、停止、別サービスへの切替えは行いません。

## 失敗した場合

一時的な接続失敗、読み込みのタイムアウト、予定終了前のEOF、通信相手の切断では、最大3回開き直します。待機時間は1秒、2秒、4秒です。残り60秒未満、明示停止、対象サービスなし、要求拒否、応答形式不正、ファイルやDBの失敗では開き直しません。

再接続後も同じ`.ts.partial`ファイルへ書き続けます。通信が切れていた間の欠損は補完しません。プロセスを再起動した後は旧い部分ファイルへ追記しません。

| 状況 | 保存結果 |
|---|---|
| 予定終了まで書き込み、完成処理も成功 | `.ts`の完成ファイル |
| 一時切断後に再接続し、予定終了まで書き込んだ | `.ts`の完成ファイル。終了理由で再接続ありと区別 |
| 利用者が停止し、188バイト以上を保存 | `.ts`で公開する部分録画。正常完了とは区別して再生可能 |
| 利用者が停止し、188バイト未満を保存 | 完成名を公開しない取消し結果 |
| 3回開き直しても回復しない | 保存済みの量に応じた部分録画または失敗結果 |
| 途中終了したが188バイト以上を保存 | `.ts.partial`の部分ファイル |
| 接続前または188バイト未満で失敗 | 失敗結果。作成済みの部分ファイルは自動削除しない |
| 完成ファイル名が既に存在 | 上書きせず、完成処理を失敗として残す |
| DBの最終確定に失敗 | ファイルを成功扱いせず、次回起動の復旧対象にする |

エラー出力には、MirakurunのURL、認証情報、絶対パス、番組名、レスポンス本文、放送データを含めません。

## 再起動時の復旧

`recording serve`を起動するたびに、DBへ記録済みのファイルだけを100件ずつ確認します。録画保存先全体は
走査しません。

- 録画途中のファイルへ追記しない
- 完成処理の途中だと確認できる場合だけ、残りの処理を続ける
- DBに保存した完成予定を読み、利用者停止の部分録画を正常完了へ変えない
- 完成ファイルがない場合は、過去の成功結果を消さず、現在の状態を「欠落」にする
- サイズ違い、symlink、特殊ファイルは成功に直さず「不一致」にする
- 不明なファイルを取り込んだり削除したりしない

同じ復旧を繰り返しても、新しい録画やファイルは増えません。

## 初期版の制限

- 同時録画の既定値は一件です。1～8件の範囲で明示できますが、提供元と保存先の能力は自動判定しません。
- 開始から5分を超えた予約、または残り60秒未満の予約は開始しません。
- 予約変更は録画開始前の対応済み録画設定に限ります。録画後の電源操作とチューナー指定には対応していません。
- 録画中の停止では、利用者が止めた一件だけを部分録画として公開します。通信障害など、別の理由で途中終了した録画は公開しません。
- 録画中の番組時刻変更は、同じ開始時刻の終了延長だけに対応します。短縮と開始時刻変更には対応していません。
- 再接続は通信上の欠落を補完せず、映像の連続性を保証しません。
- 録画履歴APIは自動テスト済みです。Komorebi向けの一覧、詳細、直接再生、30秒送りは公式APKのAndroid画面でも確認しました。Android TV実機では未確認です。
- KonomiTVのライブAPIと、公式Komorebi APKのAndroid主画面・二画面からの直接ライブを実通信で確認済みです。Android TV実機は未確認です。
- 局ロゴはKonomiTVのロゴAPIとKomorebi相当の実通信まで確認済みですが、両クライアントの画面では未確認です。
- 自動予約の録画済み番組名照合は、新規予約の無効化、既存予約の無効化、再起動後の重複防止を実MirakurunとKonomiTVで確認済みです。同じチャンネル内だけを照合する指定は自動テストで確認しています。電源操作、強制チューナー、ワンセグ別出力には未対応です。
- 実MirakurunとKonomiTV v0.14.1を使い、画面からの予約、約26分の録画、録画中の番組表更新、録画済み一覧からの再生開始を確認済みです。
- 通信を一度切った実環境の録画で、再接続、録画完了、KonomiTVからの再生開始を確認済みです。
- 4台のチューナーを持つMirakurunで異なる2局を約5分間同時に録画し、両方の完成、バックアップ、再起動後の読み出しを確認済みです。
- 録画処理は余白を反映した予定開始時刻に始めます。既定値は番組開始の5秒前です。
- 長時間運転と幅広い環境での互換性は未確認です。
