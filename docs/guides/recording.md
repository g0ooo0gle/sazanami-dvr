# 予約と録画を使う

このページでは、KonomiTV v0.14.1から予約を追加し、Sazanami DVRで録画する方法を説明します。

初回は「前提」から「録画済み番組を確認する」まで読み、録画中の停止や放送途中の予約が必要なときは該当する章を参照してください。

## 前提

次の準備を終えてください。

- Sazanami DVRが起動している
- DBの状態が`CURRENT`である
- 番組表とチャンネル設定が準備できている
- KonomiTVの`backend`が`EDCB`になっている
- KonomiTVから録画保存先を読み取れる

準備がまだの場合は、[チャンネルと番組表を準備する](channels-and-epg.md)と[KonomiTVと接続する](../getting-started/konomitv.md)を先に確認してください。

## 予約から録画まで

KonomiTVの番組表から番組を選び、予約を追加します。Sazanami DVRは予約を保存してから成功を返し、予約に指定された番組とサービスの情報を使って録画します。

通常の録画は、予約に設定された前後の余白を反映して開始します。標準の余白は、番組開始の5秒前と番組終了の2秒後です。

録画中は、KonomiTVの予約一覧で録画中の状態を確認できます。正常に番組が終了すると、録画保存先に`.ts`ファイルが作成されます。

## 自動予約について

KonomiTV v0.14.1には自動予約の画面がありません。KonomiTVの公開HTTP APIを利用するクライアントから、条件の追加、一覧、変更、削除を行えます。

保存した条件は番組表の更新後に評価され、条件に合う番組の予約が作られます。対応していない録画設定を含む条件からは予約を作りません。

## 放送中の番組を途中から録画する

放送中の番組を新しく予約した場合、次の条件を満たせば現在時刻から録画を始めます。

- 前後の録画余白を反映した開始予定時刻を過ぎている
- 予約を作成してから5分以内である
- 録画余白を反映した終了予定時刻まで60秒以上残っている

この場合、番組の冒頭からではなく、録画を開始した時点から保存します。過ぎた時間を後から補完することはありません。

録画サービスが停止したまま、余白を反映した開始予定時刻から5分を超えた予約は、再開後に遅れて録画を始めません。終了予定まで60秒未満の場合も途中録画を開始しません。

途中から録画を始めても、以降の録画、再接続、番組時刻の変更、録画終了の扱いは通常の録画と同じです。

## 予約を変更・取り消す

録画開始前の予約は、KonomiTVから有効・無効、優先度、番組追従、前後の余白、録画先、ファイル名、字幕・データ放送、録画後の動作を変更できます。

録画処理が始まった後の予約設定変更はできません。録画開始前にKonomiTVから取消し操作を行うと、予約は終了し、録画ファイルは作成しません。

## 録画中に停止する

録画開始後にKonomiTVから同じ取消し操作を行うと、録画中の一件を停止します。指定した一件だけを停止し、ほかの録画や番組表の更新は止めません。

停止時の結果は、保存できたデータ量によって変わります。

| 停止時の状態 | 結果 |
|---|---|
| 188バイト以上を保存し、確定処理に成功した | 部分録画として`.ts`名で公開し、再生可能にする |
| 188バイト未満、または確定処理に失敗した | 完成ファイルとして公開しない |
| すでに録画終了処理へ入っていた | 停止しない |
| すでに終了した予約だった | 停止しない |

確定処理にはファイルの同期とクローズ、完成名への公開、DBの確定、保存先ディレクトリの同期が含まれます。部分録画は予定終了まで録画したものではなく、録画一覧では通常終了した録画と区別されます。

## 録画済み番組を確認する

KonomiTVは、設定された`recorded_folders`を走査して録画済み番組を表示します。

KonomiTVで録画済み番組として扱うには、完成した`.ts`ファイルが必要です。短すぎるファイルは、KonomiTV側の一覧対象にならない場合があります。

Sazanami DVRとKonomiTVを別ホストで動かす場合は、録画保存先をKonomiTVホストへ共有してください。Sazanami DVRから見える録画先と、KonomiTVの`recorded_folders`に指定する録画先が異なる場合、一覧表示や再生ができません。

## 受信品質に警告がある場合

v1.4.0では、パケットの連番や番組情報の乱れを検出しても、それだけで録画を止めません。
保存できる完全なTSパケットを継続して保存し、受信品質を録画結果とは別に記録します。失われた映像の補完や、壊れたデータの修復は行いません。

品質はSazanami DVRの履歴API（`/api/recordings`、`/api/recordings/<id>`）の`quality`に含まれます。

| `quality.status` | 意味 |
|---|---|
| `UNKNOWN` | 未測定、または処理が中断して観測が完了していない。旧録画もこの値になる |
| `NO_ISSUES_OBSERVED` | 観測した範囲では異常を検出しなかった |
| `DEGRADED` | 受信の乱れ、選別方式の切り替え、通信切断などを検出した |

字幕・データ放送を除外するための情報を読めなくなった場合は、録画を止めず、元のサービスストリームを保存する方式へ切り替えます。
この場合は`selection_unverified=true`となり、除外指定した字幕・データ放送が混入することがあります。予約の設定自体は変更しません。

`quality`には分類ごとの件数も含まれます。`UNKNOWN`の0件は未測定を表し、正常の証明ではありません。
`observation_limited=true`は観測対象の上限に達したこと、`counters_saturated=true`は件数が集計上限に達したことを表します。
連番の飛びの件数は、失われた映像やパケットの数量ではありません。通常終了した録画でも、内容に欠けや乱れがある場合があります。

品質情報はNative履歴APIへの追加で、CtrlCmdの応答形式は変えていません。KonomiTV・Komorebiの画面に品質欄を追加する変更は含みません。
今回の品質警告・通信部分録画は合成データの自動テストで確認しており、実放送、NAS、クライアント画面での一覧・再生は未確認です。

## 録画が失敗した場合

一時的な通信切断や予定終了前の接続終了では、同じ録画ストリームへ最大3回まで再接続します。再接続しても、切断中に失われた放送データを補完することはありません。

| 状況 | 保存結果 |
|---|---|
| 予定終了まで録画できた | 完成した`.ts`ファイル |
| 一時切断後に復旧した | 完成した`.ts`ファイル |
| 予定終了前の接続終了・タイムアウト・再接続の試行枯渇 | 条件を満たせば再生可能な部分録画 |
| 接続拒否・不正な応答・ファイルやDBのエラー | 完成ファイルとして公開しない |
| 利用者が停止した | 条件を満たせば再生可能な部分録画 |
| プロセスを強制終了した | 次回起動時に確認が必要になる場合がある |

強制終了を避け、通常はサービス停止または`SIGTERM`を使用してください。

通信による部分録画の公開対象は、`STREAM_ENDED_EARLY`、`STREAM_TIMEOUT`、`STREAM_RECONNECT_EXHAUSTED`の3種類です。
新しい録画で188バイト以上の完全なTSパケットを保存し、実録画時間が1秒以上で、ファイルとDBの確定処理まで成功した場合に公開します。
`STREAM_UNAVAILABLE`などの結果や、更新前の非公開部分録画を、自動で公開することはありません。
短いファイルや受信状態の悪いファイルは、公開されてもクライアントの一覧・再生で扱えない場合があります。

## 完成録画を削除する場合

完成した録画ファイルをKonomiTVの管理画面から削除する操作は、予約の取消しや録画中停止とは別の機能です。

KonomiTVから完成録画を削除するには、削除を明示したDocker Compose構成が必要です。通常構成では、KonomiTVから録画保存先へ書き込めません。

詳しくは、[Docker Composeで起動する](../getting-started/docker-compose.md)を参照してください。
