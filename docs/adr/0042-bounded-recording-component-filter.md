# ADR-0042: 字幕とデータ放送は録画ごとの上限付きTSフィルターで選別する

- Status: Accepted
- Date: 2026-08-10
- Deciders: Project owner（v1.0までの判断をCodexへ委任）

## 背景

KonomiTV v0.14.1の予約画面は、字幕とデータ放送を既定、含める、含めないから選べる。Sazanami DVR v0.0.20は全体既定の`service_mode=0`だけを受け付け、ほかの選択を含む予約を失敗させる。

Mirakurun 4.1.3のサービスstreamは、PMTの全elementary PIDを中継する。要求queryで字幕やデータ放送を除外できない。値の保存と読戻しだけを追加しても、録画ファイルの内容が設定と一致しない。

## 判断

予約へ、全体既定または字幕・データ放送の明示組み合わせを保存する。全体既定は、2060で公開済みの字幕あり・データ放送なしとする。CtrlCmdの未知bitは拒否し、個別指定bitがない値はKonomiTVの読取り規則と同じく全体既定へ正規化する。

両方を含める録画は、提供元streamを変更せず保存する。どちらかを除外する録画だけ、録画executor内の小さい逐次フィルターを通す。PATから一つのPMTを特定し、PMTのstream type `0x06`と`0x0D`を選択に応じて除き、section長、version、CRCを作り直す。除外したPIDのpacketも保存しない。

最初の有効なPATとPMTを確認するまで、最大1 MiBだけ保持する。PSI sectionは1,024バイト、追跡PIDは64件を上限とする。packetは188バイト単位で処理し、stream全体や番組全体を保持しない。PMTを確認できない、形式が不正、上限を超える場合は`STREAM_FORMAT_INVALID`としてその録画を失敗させ、別設定へ自動変更しない。

schema 10で正規化済みの選択を予約へ保存する。自動予約は、実行可能な同じ設定を作成予約へ引き継ぐ。ライブ視聴は録画設定を持たないため変更しない。

## 理由

提供元にない選択機能をSazanami側で補えば、KonomiTVの表示値と実録画を一致させられる。録画ごとに限定した逐次処理なら、TS全体の保持、新しいdaemon、外部process、ライブラリを増やさずに済む。

EDCBと同じstream typeの分類に限定することで、独自の番組内容解析を避けられる。形式を確認できない場合に録画を止めれば、「除外した」と表示しながら対象PIDを残す誤動作も防げる。

## 影響

- 既定録画はデータカルーセルを除外するため、v0.0.20以前より録画byte数が小さくなる場合がある。
- TS packetの検証とPMT再生成が録画経路へ加わる。
- 不正または非標準の提供元streamは、選別を必要とする設定では録画失敗になる。
- schema migrationと更新前backupが一つ増える。

## 採用しなかった案

### 設定値だけ保存する

録画内容が選択と一致せず、KonomiTVへ誤った成功を返すため採用しない。

### 常に字幕とデータ放送を残す

データ放送を含めない全体既定と、画面の明示選択を満たさないため採用しない。

### 外部TS処理programを呼ぶ

導入、停止、失敗、license、引数の安全性が増える。必要な選別は小さく固定できるため採用しない。

### ライブ視聴にも同じ選別を行う

ライブ操作は予約設定を持たず、現在の利用経路を変える理由がないため対象外とする。
