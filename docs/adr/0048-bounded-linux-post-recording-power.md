# ADR-0048: 録画後の電源動作は録画終了後に一度だけ調整する

- Status: Accepted
- Date: 2026-08-10
- Deciders: Project owner（v1.0までの判断をCodexへ委任）

## 背景

KonomiTV v0.14.1は、予約と自動予約でスタンバイ、休止、復帰後再起動、シャットダウンを指定できる。Sazanami DVR v0.0.27はこれらを未対応として予約全体を失敗させる。

録画を終えた処理から直ちに電源を切ると、同時録画、次の予約、録画後スクリプトを壊す。単に設定を保存して何もしなければ、KonomiTVの表示と実際の動作が食い違う。Linuxでは復帰時刻の設定、systemdの権限、機器のRTC対応も必要である。

## 判断

`DEFAULT`と`NOTHING`に加え、`STANDBY`、`STANDBY_REBOOT`、`SUSPEND`、`SUSPEND_REBOOT`、`SHUTDOWN`を予約へ保存する。CtrlCmdの2013、2015、2011と自動予約で、KonomiTVの値を同じ意味のまま往復する。

電源動作は録画処理の中で実行しない。完成録画を公開し、DBの終了状態を確定し、録画後スクリプトが終わった後に、録画schedulerへ候補を返す。schedulerは次の条件をすべて満たす場合だけ一度実行する。

- 実行中の録画が0件である。
- 同時期に完了した電源動作の候補が一種類だけである。
- 次の有効予約まで10分以上ある。
- 次の予約がある場合は、予定開始の5分前をRTCの復帰時刻として設定できる。

異なる電源動作が競合した場合、次の予約が近い場合、RTC設定に失敗した場合は、電源状態を変えず候補を破棄する。自動再試行はしない。プロセス再起動後に過去の候補を再実行しない。

Linux adapterは起動時に`systemctl`と`rtcwake`を一度だけ解決する。RTC設定には`rtcwake --mode no --time`、電源動作には`systemctl --no-ask-password`を使う。復帰後再起動では、スタンバイまたは休止から戻った後に`systemctl reboot`を実行する。shell、`sudo`、PATHの再検索、標準入出力の記録は行わない。

次の予約がなければRTCを設定せずに電源動作を試みる。次の予約がある場合は、RTCを設定できなければ電源動作を行わない。電源要求が失敗または復帰後に戻った場合は、残ったRTC alarmを解除する。

DB形式は第12版へ更新する。既存の`post_action_mode`は`DEFAULT`と`NOTHING`の互換値として残し、新しい電源動作だけを`post_power_mode`へ保存する。二つを同時に有効にしない制約を持たせる。更新前backupを必須とする。

## 理由

録画schedulerは実行中件数と次の予約を既に管理している。ここへ小さい調整処理を置けば、別daemonや常駐queueを増やさず、同時録画が終わる前の電源断を防げる。

systemdへ通常の要求を送れば、OS側の権限と抑止機能を利用できる。RTCの設定に失敗した状態で休止しなければ、次の予約を見逃す危険を減らせる。

## 影響

- schema 12への明示migrationと事前backupが必要になる。
- systemdまたはRTCが利用できない環境では、電源設定の保存はできても実行時に固定診断を残して何もしない場合がある。
- 録画後スクリプトの終了まで電源動作は待つ。
- 実験環境で実際にスタンバイさせる試験は、復帰手段を事前確認できた場合だけ行う。

## 採用しなかった案

### 設定だけ保存して実行しない

KonomiTVの画面では有効に見えるため、利用者の意図と実際の動作が食い違う。

### 録画処理ごとに直ちに実行する

同時録画と録画後スクリプトを途中で止めるため採用しない。

### `sudo`やshellを介して実行する

対話待ち、文字列解釈、設定依存が増える。必要なOS権限はsystemd／polkit側で明示する。

### RTC設定に失敗しても休止する

次の予約まで復帰できない可能性があるため採用しない。
