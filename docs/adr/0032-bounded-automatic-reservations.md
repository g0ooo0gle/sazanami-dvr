# ADR-0032: 自動予約は完成済み番組表を上限付きで評価する

- Status: Accepted
- Date: 2026-08-09
- Decision owner: Project owner
- Delegated reviewer: Codex
- Authorization: Project ownerはv1.0.0までの技術判断と必要なDB変更をCodexへ委任した
- Related: ADR-0026、Plan 0040、Plan 0045、Handoff 0020

## 背景

Sazanami DVR v0.0.7は、完成済み番組表を使う単発予約と録画を提供している。KonomiTVとKomorebiがEDCBバックエンドへ送る自動予約操作には、一覧2131、追加2132、変更2134、削除1033がある。

自動予約をメモリだけで管理すると、再起動後に条件と重複判定を失う。別daemonや内部queueを追加すると、番組表、予約、録画との所有関係が増える。一方、現在の番組表DBはジャンル、映像形式、音声形式を保存していないため、すべてのEDCB検索条件を正しく評価できない。

## 判断

自動予約条件と、その条件から作成した予約の対応をSQLiteへ保存する。条件はKonomiTVが送る検索条件と録画設定を欠落なく読み戻せるドメイン型へ変換し、CtrlCmdのbyte列を正本として保存しない。

評価は、同じ常駐録画プロセスが番組表を正常に更新して公開し、予約時刻の追従を終えた後だけ一回行う。別daemon、polling、内部queue、worker poolは作らない。番組表更新は自動予約より先に成功として確定し、自動予約の失敗によって完成済み番組表を失敗扱いへ戻さない。

現在の番組表から確実に判定できる文字列、正規表現、除外、サービス、曜日と時刻、番組長、無料／有料だけを評価する。必要な情報がない条件は無視して広く一致させず、その規則から予約を作らない。規則、番組、比較回数、新規予約数には固定上限を設ける。

自動予約は既存の番組照合と予約保存を使う。同じ番組インスタンスに既存予約がある場合は、別規則からも新しい予約を作らない。規則と番組の対応を永続化し、再起動や番組表の再同期で同じ予約を作らない。

既存DBは、明示的なmigrationと検証済み事前backupがある場合だけ更新する。通常起動は古いDBを自動変更しない。

## 結果

- KonomiTV APIとKomorebiが条件を保存、一覧、変更、削除できる。
- 自動予約は番組表の更新順と同じプロセス内に収まり、追加の常駐構成を必要としない。
- 判定材料が不足する条件による誤予約を防げる。
- 第5版DBへ移行した後は、v0.0.7へ戻す前にbackupのrestoreが必要になる。
- 高度な条件は読み書きできても、後続実装まで予約を作らない。この差は公開互換表に表示する必要がある。

## 採用しなかった案

### CtrlCmdの要求byte列をそのまま保存する

不採用。ドメインとDBがCtrlCmd形式へ依存し、別APIや将来の形式変更で再利用できない。

### 判定できない条件を無視して残りの条件だけで予約する

不採用。利用者の指定より広い範囲を録画する危険がある。

### 自動予約専用daemonを作る

不採用。番組表更新と予約作成の順序、DB所有権、停止手順が複雑になる。同じ常駐プロセスの正常更新後に一回呼べば足りる。

### 先に番組表schemaを全面拡張する

不採用。今回確実に使える文字列とサービス条件まで遅らせる。ジャンル等は番組検索と共通化する後続変更で追加する。
