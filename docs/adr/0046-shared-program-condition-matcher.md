# ADR-0046: 番組検索と自動予約は同じ条件判定を使う

- Status: Accepted
- Date: 2026-08-10
- Decision owner: Project owner
- Delegated reviewer: Codex
- Authorization: Project ownerはv1.0.0までの技術判断をCodexへ委任した
- Related: ADR-0032、ADR-0035、ADR-0036、Plan 0061

## 背景

Sazanami DVR v0.0.25は、番組検索でジャンル、あいまい検索、映像、音声を評価できる。一方、自動予約では同じ条件を保存できても、判定不能として予約を作らない。番組metadataと検索条件のdomain型は既にあるため、新しいDB項目は不要である。

同じ条件を二か所で別々に実装すると、大文字小文字、かな、ジャンル除外、metadata不足などの扱いがずれやすい。CtrlCmd adapter内の判定をapplicationから直接呼ぶと、依存方向も逆になる。

録画済み番組名の照合は、現在番組だけでなく録画履歴を読む必要がある。録画後の電源操作なども、番組条件とは別の安全境界を持つ。

## 判断

通信形式から独立した自動予約coreに、準備済みの番組条件判定を置く。番組検索1025と自動予約評価は、文字列、正規表現、番組名限定、あいまい検索、ジャンル、ジャンル除外、映像、音声、日時、日時除外、番組長、無料・有料の判定を共有する。

正規表現は条件ごとに一度だけ準備する。不正な正規表現はcoreの固定errorとし、番組検索は既存の安定した失敗理由へ変換する。自動予約は該当規則から予約を作らず、ほかの規則の評価を続ける。

放送サービスの照合は共通判定へ入れない。番組検索は固定した対象サービスだけを走査し、自動予約は番組を予約要求へ変換した後で三つの放送IDを照合する。録画済み番組名照合と未対応録画設定は今回有効にしない。

DB schema、CtrlCmd形式、評価時点、比較回数、作成件数、番組検索の応答上限は変更しない。新しいcache、worker、外部依存は追加しない。

## 結果

- KonomiTVとKomorebiが保存する主要な番組条件を、自動予約でも評価できる。
- 番組検索と自動予約の意味が一つの実装で揃う。
- DB migrationなしで既存規則をそのまま再評価できる。
- 録画済み番組名照合と一部の録画設定は、引き続き保存のみで予約を作らない。

## 採用しなかった案

### 自動予約へ同じ判定を複製する

不採用。二つの実装を維持することになり、互換修正の漏れを防げない。

### CtrlCmd番組検索adapterを自動予約から呼ぶ

不採用。coreとapplicationが通信形式、codec、失敗応答へ依存する。

### 録画済み番組名照合も同時に実装する

不採用。録画履歴を読む期間、件数、タイトル正規化、削除済み記録の扱いを別に決める必要がある。

### 判定結果を永続化する

不採用。番組表世代と規則変更に対する無効化が増える。既存の固定上限内で、その場で判定すれば足りる。

## 安全性と個人情報

検索語、番組名、詳細、ジャンル、接続先、生の要求と応答を通常ログへ出さない。入力文字列、metadata、規則、番組、比較、作成予約の既存上限を維持する。判定不能を条件無視による広い一致へ変換しない。
