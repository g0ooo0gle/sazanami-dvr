# ADR-0041: 録画先とファイル名を保存ルート内の相対指定として扱う

- Status: Accepted
- Date: 2026-08-10
- Decision owner: Project owner
- Delegated reviewer: Codex

## 背景

KonomiTV v0.14.1は予約の追加と変更で、録画先フォルダー、`Write_Default.dll`、`RecName_Macro.dll`のファイル名テンプレートを送る。Sazanami DVR v0.0.18は空の録画先だけを受けるため、画面でこれらを指定すると予約操作が失敗する。

KonomiTVとSazanamiは別ホストで動く場合があり、KonomiTVから送られる絶対パスをSazanamiのホストパスとして安全かつ一意に解釈できない。一方、Sazanamiは起動時に録画保存ルートを明示し、既存の録画保存adapterがその内側だけを扱っている。

## 決定

KonomiTVから受ける録画先は、Sazanamiの録画保存ルートからの相対フォルダーとして扱う。空は既定保存先、非空は検証済みの相対パスだけを受ける。絶対パス、親参照、Windowsドライブ、ネットワーク共有、環境変数の展開は行わない。

通常録画先は0件または1件に限定する。書き込みプラグインは`Write_Default.dll`、ファイル名プラグインは`RecName_Macro.dll`だけを受ける。テンプレートのマクロは、予約が持つ番組名、放送局名、時刻、放送時間、放送ID、予約番号から決定できる固定一覧だけをGoで展開する。外部プラグインや外部processは実行しない。

検証済みのフォルダーとテンプレートを予約へ保存し、録画処理の確保時に部分ファイルと完成ファイルの相対パスへ変換する。確保後は同じ`FilePlan`を正本とし、番組表更新や設定変更から名前を作り直さない。既存ファイルは上書きせず、同名なら録画を安定した失敗へ進める。

旧DBの予約は空のフォルダーとテンプレートへ移行する。DB移行前バックアップを必須とし、旧版へ戻す場合は旧実行ファイルと移行前DBを組にして戻す。

## 理由

録画保存ルートを唯一の境界にすれば、別ホストの絶対パス対応表や追加設定を持たずに、KonomiTVの設定を実際の保存へ反映できる。マクロを内部値だけから決定的に展開すれば、外部DLL、shell、環境変数、現在ディレクトリへ依存しない。予約とファイル計画を分ける既存設計も維持できる。

## 影響

- 利用者はKonomiTVの録画先欄へ、Sazanamiの録画保存ルートからの相対フォルダーを入力する。
- EDCBやKonomiTVホストの絶対パスをそのまま入力した予約は失敗する。
- 対応マクロ以外を含むテンプレートは、保存時に`recording-setting-out-of-profile`として失敗する。
- schema migrationが一つ増える。移行前backupとrestoreが必要になる。
- 完成TSの形式、再生URL、録画履歴の公開形式は変わらない。

## 採用しなかった案

### 任意の絶対パスを許可する

保存ルート外への書き込み、別ホストでの意味の違い、権限と復旧の複雑さが増えるため採用しない。

### パスの先頭を削って相対パスへ自動変換する

異なる入力が同じ保存先になり、利用者が指定した結果を予測できないため採用しない。

### EDCBの全マクロと関数を再実装する

固定クライアントが通常の予約画面で必要とする範囲を超え、番組詳細や外部プラグインへの依存が増える。対応一覧を明示し、必要なマクロだけを追加する。

### 予約保存時に完成ファイル名まで固定する

既定名は録画処理IDで衝突を避ける既存設計を維持したい。要求値を予約へ保存し、録画処理の確保時に一度だけファイル計画を作る。
