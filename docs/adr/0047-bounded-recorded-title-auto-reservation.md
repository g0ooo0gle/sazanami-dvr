# ADR-0047: 録画履歴を一度だけ索引化し、一致する自動予約を無効にする

- Status: Accepted
- Date: 2026-08-10
- Decision owner: Project owner
- Delegated reviewer: Codex
- Authorization: Project ownerはv1.0.0までの技術判断をCodexへ委任した
- Related: ADR-0032、ADR-0033、ADR-0046、Plan 0062

## 背景

Sazanami DVR v0.0.26は、KonomiTVが保存する録画済み番組名の照合条件を読み書きできるが、その条件を持つ規則を判定不能としている。固定版KonomiTVとEDCBは、期間内に同名の録画履歴があると、自動予約を削除せず無効状態で残す。

番組ごとに録画履歴をDB検索すると、最大4,194,304回の条件比較にDB処理が加わる。録画履歴全体を無制限に読むこともできない。一方、既存の録画履歴には256件のページと16,384件の全体上限があり、番組名、開始時刻、放送IDも保持している。

## 判断

録画済み番組名の照合を使う規則が一つでもあり、対象日数が1日以上なら、評価開始前に録画履歴を一回だけ上限付きで読む。番組名ごとの最新開始時刻と、番組名・ONID・TSID・SIDごとの最新開始時刻をメモリへ保持する。DB schemaと新しい永続cacheは追加しない。

将来番組名と録画履歴の番組名は完全一致で比べる。比較対象は録画履歴に残る終了済み録画とし、結果の成否では除外しない。期間の下限は将来番組の開始時刻から指定日数を引いた時刻で、履歴の開始時刻が下限より後の場合だけ一致する。0日は一致なしとする。同じチャンネルではONID、TSID、SIDも一致させ、全チャンネルでは放送IDを比較しない。

一致した新規予約は無効状態で作る。同じ番組の自動予約が既に有効なら、録画処理が始まっていない場合だけ無効へ変える。自動予約の対応表にない手動予約や、録画処理を開始済みの予約は変更しない。

録画履歴の読取り、件数、順序、値に異常があれば、番組評価と予約変更を始める前に処理を失敗させる。検索語、番組名、録画履歴、放送局をログへ出さず、件数と成否だけを記録する。

## 結果

- KonomiTVの録画済み番組名条件を、保存だけでなく実際の自動予約へ反映できる。
- 評価ごとのDB読取りは録画履歴一回に限られ、番組との照合はmap参照になる。
- DB migration、新しい依存、常駐worker、永続cacheは不要である。
- 最大16,384件、番組名4,096バイトという既存上限の範囲でメモリ使用量が決まる。
- EDCB固有の`RecInfo2RegExp`設定は再現せず、保存済み番組名をそのまま比較する。

## 採用しなかった案

### 番組ごとにDBへ存在確認する

不採用。検索条件が広いとDB問い合わせが数百万回になり得る。

### 録画済みなら予約を作らない

不採用。規則を削除しない限り次の評価で予約が再作成され、固定版KonomiTVとEDCBの扱いとも異なる。

### 録画済み一覧の成功項目だけを対象にする

不採用。固定版EDCBは録画結果で除外せず、録画履歴に残る終了項目を照合する。

### 番組名の正規化設定を追加する

不採用。固定版KonomiTVのAPIから操作できず、初期互換に不要な設定面と正規表現実行を増やす。

## 安全性と個人情報

履歴読取りは予約変更より先に完了させる。上限超過や途中失敗を条件無視へ変換しない。手動予約と開始済み録画を変更しない。番組名、放送局、接続先、利用者名、録画path、生の要求・応答をGit、通常ログ、実験報告へ残さない。
