# ADR-0035: 番組検索は完成済み番組表を上限付きで二回走査する

- Status: Accepted
- Date: 2026-08-09
- Decision owners: Project owner
- Delegated reviewer: Codex
- Related: ADR-0023、ADR-0026、ADR-0027、Plan 0040、Plan 0048

## Context

KonomiTV v0.14.1の番組検索画面は、CtrlCmd 1025へ検索条件を送り、番組情報の一覧を受け取る。製品v0.0.10は、同じ条件形式に近い自動予約と、同じ番組情報形式を返す1029を実装済みだが、1025は未対応である。

Sazanamiは、失敗した番組表更新で以前の完成済み番組表を置き換えない。検索中に世代が切り替わると、応答サイズを測った番組と実際に書く番組が変わり得る。検索結果全体をメモリへ保持すれば避けられるが、最大件数に対して不要なメモリを使う。

現在の番組表はジャンル、映像、音声を保存していない。判定できない条件を無視すると、利用者が指定した条件より広い結果を成功として返す。

## Decision

検索は要求開始時に一つの完成済み番組表世代を固定する。256件ずつ読み、最初の走査で一致件数と応答サイズを測り、二回目の走査で同じ条件を適用しながら逐次出力する。結果全体をメモリへ保持しない。

検索条件はCtrlCmd adapterで厳密に読み、中核の検索条件へ変換する。番組情報の大きさ計算と出力は1029の既存変換を共有する。検索結果は最大262,144件、応答本文は最大256 MiB、同時生成は一件とする。

現在の保存項目だけで判定できるキーワード、除外語、番組名限定、大文字小文字、正規表現、放送局、曜日と時刻、番組長、無料・有料を扱う。無効な条件は空一覧とする。ジャンル、映像、音声、根拠を固定できていないあいまい検索は、条件を無視せず未対応として失敗させる。

DB schema、番組表の取得項目、提供元への通信はこの変更では変えない。

## Consequences

通常の番組検索をKonomiTVから使える。検索は最後に正常取得できた番組表だけを読み、取得元へ都度接続しない。二回走査のため読み取り量は増えるが、メモリ使用量はページと小さい集計に制限できる。

ジャンルとあいまい検索はv0.0.11時点で未対応のままである。公開互換表で分けて表示し、番組詳細の保存項目を増やした後に同じ1025へ追加する。

## Rejected alternatives

### 検索結果を一度にメモリへ集める

不採用。応答上限に近い検索で不要な大きな配列を作る。既存の1029と同じ二回走査で足りる。

### 判定できない条件を無視する

不採用。ジャンル指定などが全件検索へ広がり、利用者の指定を満たしていないのに成功して見える。

### 検索のたびにMirakurunへ問い合わせる

不採用。通常の画面操作が暗黙の外部接続になり、失敗中の番組表と完成済み番組表が混ざる。完成済み番組表を正本として読む。

## Security and privacy

検索語、除外語、番組名、放送局、接続先、生の要求と応答を通常ログへ出さない。未対応や失敗は固定した短い理由だけを返す。LAN待受の既定と上限は変更しない。
