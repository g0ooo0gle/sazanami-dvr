# ADR-0039: 予約設定は要求値と録画に使う実効値を分けて保存する

- Status: Accepted
- Date: 2026-08-09
- Deciders: Project owner, Codex（v1.0までの委任範囲）
- Supersedes: None
- Superseded by: None

## 背景

KonomiTV v0.14.1は、予約の有効／無効、優先度、開始・終了の余白を2013と2015へ送る。余白を省略した場合は`EpgTimerSrv.ini`の全体既定を使い、2011でも「既定を使う」と読み戻せることを前提にする。

Sazanami DVR v0.0.11は無効予約と個別余白を拒否する。2060で開始5秒前、終了2秒後を返す一方、DBの余白は0秒に固定されている。スケジューラの固定5秒先行起動により開始側だけが偶然近い挙動になるが、DBの予定時刻と終了側は一致しない。

## 決定

予約へ有効値、既定余白を使うかどうか、実効開始余白、実効終了余白を保存する。既定値は開始5秒、終了2秒とする。2011は既定／個別の選択を返し、スケジューラと録画処理は実効値を使う。個別指定では要求値と実効値が同じなので、別々の列へ重複保存しない。

個別余白は開始と終了を一組で受け、各-3,600～3,600秒とする。予定開始を番組開始から開始余白だけ前へ、予定終了を番組終了から終了余白だけ後ろへ動かす。結果の録画時間は1秒以上24時間以内でなければならない。

無効予約は未完了予約としてDBと2011に残し、録画処理とファイルを作らない。2015で再び有効にできる。予定終了を過ぎた無効予約は、スケジューラが一件ずつ`FINISHED/DISABLED_EXPIRED`へ進める。

録画枠が空いた時に開始期限内の予約が複数あれば、優先度が高い順、予定開始が早い順、内部ID順で選ぶ。実行中の低優先度録画は止めない。未来の高優先度予約のために録画枠を空けない。

録画開始の既存5分猶予は、番組開始ではなく余白反映後の予定開始から数える。録画できる残り時間は既存どおり60秒以上を必要とする。

番組追従は要求設定を維持する。録画開始前は新しい番組時刻と同じ実効余白から予定時刻を作る。録画中の終了延長は、現在と後継の番組終了に同じ終了余白を加えて比較する。

既存DBの未完了予約は有効とし、余白は既定指定の開始5秒、終了2秒へ移行する。旧版の実行と完全には同じでないため、migration前backupを必須にする。

自動予約条件の録画モード1は有効予約、5は無効予約を作る。優先度、追従、既定／個別余白を作成予約へ引き継ぐ。検索条件自体の有効値は、条件を評価するかどうかとして別に扱う。

## 理由

「既定を使う」という利用者の選択を0秒へ変換すると、後で全体既定を読み戻せず、2011の表示とも一致しない。要求値と実効値を分ければ、クライアントへ同じ設定を返しながら、録画処理は確定した値だけを使える。

固定先行時間を余白へ置き換えると、開始と終了を同じ式で扱える。無効予約を取消しにしなければ、自動予約による再追加を防ぎつつ再有効化できる。

## 影響

- DB migrationで既存の余白CHECK制約を置き換え、有効値と既定指定を追加する。
- 既存の未完了予約は、更新後に開始5秒前、終了2秒後を実効値として使う。
- 同じ時刻に待つ予約では優先度が実行順へ反映される。
- 実行中録画の優先度による入替えは行わない。
- 保存先など、効果を実装していない設定は引き続き失敗させる。

## 採用しなかった案

### 要求した余白だけを保存する

既定指定と明示した5秒／2秒を区別できず、2011の読み戻しが変わるため不採用とする。

### 無効予約を削除する

再有効化できず、自動予約から再追加されるため不採用とする。

### 優先度で実行中録画を停止する

利用者停止とは別の終了理由と部分録画方針が必要になるため、後続判断へ分ける。
