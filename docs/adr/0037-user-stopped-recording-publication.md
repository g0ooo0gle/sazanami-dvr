# ADR-0037: 利用者が停止した録画は部分録画として完成名へ公開する

- Status: Accepted
- Date: 2026-08-09
- Deciders: Project owner, Codex（v1.0までの委任範囲）
- Supersedes: None
- Superseded by: None

## 背景

KonomiTV v0.14.1は録画中の予約削除を停止操作として提供し、停止時点までの録画ファイルを残すと画面に表示する。Sazanami DVR v0.0.11は録画開始前の取消しだけを1014で受け付け、途中終了は`.ts.partial`のまま残す。

KonomiTVの録画走査は`.ts.partial`を対象にしない。単に実行中contextを取り消すだけでは、通信は止まっても利用者が録画一覧から再生できない。また、既存の完成途中状態は正常完了だけを前提にしているため、部分録画を同じ経路へ入れると再起動後に正常完了へ誤分類する。

## 決定

CtrlCmd 1014は、録画開始前の予約取消しに加え、`CLAIMED`、`STARTING`、`RECORDING`の一件へ利用者停止を要求できるようにする。停止要求はSQLiteへ先に保存し、保存後だけ実行中録画へ通知する。`FINALIZING`へ入った録画は中断しない。

実行中通知には、内部予約IDから取消し関数を引く小さい登録表を使う。登録数は最大同時録画数以下とし、DBを正本にする。登録表は停止を早めるためだけに使い、登録前の競合、通知の取りこぼし、再起動はDBの停止要求で回復する。追加goroutineとキューは作らない。

停止時に188バイト以上を保存していれば、既存の上書きしない完成処理で通常の`.ts`名を公開する。録画処理の状態は`PARTIAL`、終了理由は`USER_REQUESTED_STOP`、ファイルの利用状態は`FINAL`とする。再生用の読取りは、この組合せだけを正常完了とは別の再生可能な部分録画として受け付ける。

188バイト未満なら完成名を公開しない。録画処理は`CANCELLED/USER_REQUESTED_STOP`とし、実際の部分ファイルまたは欠落状態を記録する。

完成処理を始める前に、予定する最終状態と終了理由をSQLiteへ保存する。再起動時はその値を読み、通常録画は従来どおり`SUCCEEDED/COMPLETED`、利用者停止は`PARTIAL/USER_REQUESTED_STOP`へ進める。利用者停止を正常完了へ変換しない。

## 理由

利用者は録画を停止した時点までの内容を残すとKonomiTVから説明される。完成名へ安全に公開すれば、KonomiTVの既存走査とSazanamiのHTTP再生をそのまま使える。状態を`PARTIAL`に保つことで、予定終了した録画との違いも失わない。

DBを先に更新すれば、停止応答後に録画が再開したり、process再起動で停止要求を失ったりしない。登録表を通知の最適化に限定すれば、CtrlCmd adapterとprovider leaseを直接結合せずに済む。

## 影響

- 録画開始後の1014が成功し、一件だけを停止できる。
- 利用者停止の録画は再生できるが、番組の末尾がなく、TSの連続性や完全性は保証しない。
- SQLite migrationで停止要求と完成処理の予定結果を保存する。
- 再生可能の判定は、正常完了に加えて利用者停止の部分録画を明示的に扱う。
- 通信障害、容量不足、プロセス終了など、利用者停止以外の部分録画は自動で完成名へ公開しない。

## 採用しなかった案

### 部分名のまま残す

KonomiTVから見つけて再生できないため不採用とする。

### すべての部分録画を完成名へ公開する

ファイル破損、容量不足、DB失敗などの録画まで通常の一覧へ混ぜるため不採用とする。利用者が明示的に止めた録画だけを対象にする。

### 正常完了として扱う

予定終了前に止めた事実と運用上の成功率を失うため不採用とする。

### in-memoryの取消しだけにする

DB保存との順序、再起動、登録前の競合で停止要求を失うため不採用とする。
