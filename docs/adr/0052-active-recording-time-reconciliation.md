# ADR-0052: 録画中も検証済み番組の終了予定へ追従する

## 背景

ADR-0030は、録画開始後の変更を、開始時刻が同じ番組の終了延長だけに限定した。この判断は
誤った短縮で末尾を失う危険を抑えた一方、番組が短くなった場合や開始時刻と終了時刻が一緒に
動いた場合、不要な時間まで録画を続ける。

Project ownerは、録画中の終了前倒しと開始時刻変更を既定で反映し、従来の延長限定動作は
利用者が明示した場合だけ残す方針を採用した。先に始まった録画を後続予約のために止めないこと、
実行中ファイルを壊さないことも明示されている。

## 判断

追従を要求した予約に、最新の完成済み番組表から同じ番組の検証済み後継revisionが見つかった場合、
録画開始後も予約の番組revision、開始時刻、放送時間を更新する。対象となる録画処理は一件だけで、
状態が`CLAIMED`、`STARTING`、`RECORDING`のいずれかでなければならない。

録画処理の終了予定は、新しい番組開始時刻と放送時間から求めた番組終了に、予約の終了余白を一度だけ
加えた時刻へ変更する。後ろへの延長だけでなく、前への短縮と、開始時刻変更に伴う終了予定の変更も
受け入れる。予約と録画処理は一つのSQLite transactionで比較更新し、revision、version、状態、
現在の終了予定が変わっていた場合は更新しない。

録画処理を確保した後は、`planned_start_utc_ms`、実際の開始時刻、ファイル計画、保存済みbyteを
書き換えない。予約側には新しい番組開始時刻を保存するが、開始が後ろへ動いても保存済みの先頭を
削らず、前へ動いても過ぎた区間を取り直さない。別serviceへの切替えとretuneも行わない。

新しい終了予定が現在時刻以前なら、録画処理は次の録画開始処理または5秒ごとの進捗保存でその時刻を
読み、通常の同期・close・完成処理へ進む。contextの強制取消しやファイル削除は使わない。
新しい番組終了が確保済み開始予定以前の場合だけ、録画処理の終了予定を開始予定の1ミリ秒後へ寄せ、
SQLiteの不変条件を守る。予約には実際の番組時刻を保存する。

録画処理が受け入れる終了予定の上限は、確保済み開始予定から24時間とする。これは既存の一回の
録画時間上限と同じである。上限を超える場合は、予約と録画処理の両方を以前の値に保つ。

`recording serve`へ`--active-follow-extension-only`を明示した場合は、ADR-0030の保守的動作を使う。
この動作では、後継番組の開始時刻が同じで、終了予定が現在値より後ろへ動く場合だけ更新する。
flagを省略した通常起動では、短縮と開始時刻変更を含む新しい動作を使う。

先着録画、同時録画数、予約優先度、Mirakurunのstream割当て、録画停止の既存規則は変更しない。
後続予約と重なっても、実行中録画を中断しない。DB schema、録画ファイル形式、外部依存、
常駐処理も追加しない。

本ADRはADR-0030を置き換える。録画開始前の追従はADR-0029を維持する。両文書で録画開始後の
扱いが異なる場合は、本ADRを適用する。

## 結果

- 追従あり予約は、録画開始後の延長、短縮、開始時刻変更に伴う終了予定へ合わせられる。
- 終了予定を過ぎていた場合も、保存済みファイルを通常の終了経路で確定できる。
- 開始時刻変更前に保存した余分な区間と、変更後に取り戻せない過去区間は残る。
- 従来動作が必要な利用者は、一つのflagを明示して維持できる。
- 別番組への誤追従を避ける検証済み後継判定と比較更新は変わらない。

## 採用しなかった案

### 短縮だけを追加し、開始時刻変更は拒否する

終了予定は開始時刻と放送時間の組から決まる。開始変更だけを拒否すると、ownerが採用した動作と
一致せず、同じ番組の一つの改訂を項目ごとに分断する。

### 開始時刻変更時に録画ファイルを作り直す

保存済みデータを失い、再起動復旧と公開状態が複雑になる。現在のファイルを維持し、終了予定だけを
調整する。

### 終了予定を過ぎたら録画contextを直ちに取り消す

書込みやfile同期の途中で取消すと、既存の正常終了経路を外れる。進捗保存で時刻を読み、通常の
完成処理へ進める。

### 後続予約を優先して実行中録画を中断する

先着録画を守る決定に反する。競合は既存の同時録画上限とprovider結果へ任せる。

## 検証

- 録画処理なし、`CLAIMED`、`STARTING`、`RECORDING`、`FINALIZING`、終了状態を分ける。
- 同じ開始の延長・短縮、開始の前倒し・後ろ倒し、終了予定が過去・現在・未来の各場合を確認する。
- 予約の番組時刻と録画処理の終了予定だけが変わり、開始予定、byte数、file計画を維持する。
- 明示flagでは延長だけを受け入れる。
- 未検証revision、別instance、競合、上限超過、DB失敗で部分更新しない。
- 親cancel、利用者停止、再接続、複数同時録画、再起動、録画履歴を回帰確認する。

## 見直す条件

- providerが現在番組の確定した境界やevent relayを能力として提供する。
- 保存済み先頭区間の切出しや欠損区間の補完が、別機能として必要になる。
- 実放送の観測で、検証済み後継判定でも誤った短縮が起きる証拠が得られる。
