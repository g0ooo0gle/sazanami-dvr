# ADR-0043: 録画後スクリプトは専用ディレクトリから直接実行する

- Status: Accepted
- Date: 2026-08-10
- Deciders: Project owner（v1.0までの判断をCodexへ委任）

## 背景

KonomiTV v0.14.1は、録画後に何もしない設定と、Linuxで実行するスクリプトpathを予約ごとに送れる。Sazanami DVR v0.0.21が受け付けるのは、既定値と空pathだけである。画面で明示的に変更すると、予約の保存が失敗する。

録画後スクリプトは利用価値がある一方、CtrlCmdで受け取った任意pathを実行すれば、認証のないLAN接続口が任意program実行の入口になる。録画の完成処理と外部programの成否も分けなければならない。

## 判断

まず対象を絞る。予約へ`DEFAULT`または`NOTHING`の録画後動作と、任意のスクリプトpathを保存する。両方の動作は電源状態を変えない。KonomiTVの選択を同じ値で読み戻すため、`DEFAULT`と`NOTHING`は区別する。

実行範囲は小さく固定する。録画後スクリプトは、起動時に決めた専用ディレクトリ内だけを許可する。既定はdata root内の`post-recording-scripts`とし、利用者本人だけが書き換えられる権限で作る。予約保存時と実行直前に、次を確認する。

- pathは絶対pathで、UTF-8の1,024 byte以内である。
- 許可ディレクトリ自身と対象pathを解決した後も、対象が同ディレクトリ内にある。
- 対象はsymlinkではなく、通常ファイルで、Sazanamiの実行利用者から実行できる。

実行にはGo標準ライブラリの`os/exec`を使う。shellは介さない。引数も渡さない。環境変数は録画番号、完成ファイルpath、終了状態、終了理由に限定する。標準出力と標準エラーは捨てる。通常logへは流さない。一件につき一回、最大5分とする。自動再試行もしない。

保存と実行を分ける。スクリプトは、完成ファイルの公開とDBの終了確定が成功した後だけ実行する。対象は、正常終了と、利用者停止で再生可能な部分録画である。後処理が失敗しても録画は残す。timeoutやprocess停止を含め、短い診断理由だけを残す。スクリプト実行中は同じ録画枠を保持し、無制限の外部processを作らない。

スタンバイ、休止、復帰後再起動、シャットダウンはこの変更へ含めない。これらは予約保存時に未対応として失敗させ、次の電源動作仕様で扱う。

## 理由

専用ディレクトリに限定すれば、KonomiTVのLinux向けスクリプト欄を利用しながら、LAN入力から任意のsystem programを起動する経路を作らずに済む。shellを使わないため、空白、記号、展開文字を追加の命令として解釈しない。

録画の完成を先に確定すれば、後処理の失敗で録画ファイルや履歴を失わない。録画枠を実行終了まで保持する設計は最大並行数をそのまま外部processの上限にでき、新しいqueueやdaemonを必要としない。

## 影響

- schema 11で予約に録画後動作とスクリプトpathを追加する。
- スクリプトの実行時間中は、同じ録画枠が次の予約に使われない。
- スクリプトを使う利用者は、許可ディレクトリへ実行可能ファイルを置く必要がある。
- 電源動作を選ぶ予約は、後続実装まで保存できない。

## 採用しなかった案

### CtrlCmdで受け取った任意pathを実行する

認証のない接続口から、Sazanamiの権限で任意programを起動できるため採用しない。

### shellへ文字列を渡す

引用、展開、複数commandの解釈が増え、単一ファイルを実行する目的に不要なため採用しない。

### スクリプト失敗時に録画も失敗へ戻す

完成済みファイルとDBの事実が食い違うため採用しない。

### 電源動作も同時に実装する

複数録画の待ち合わせ、復帰後の再起動、OS権限の判断が増える。小さい変更として検証できないため分離する。
