# Mirakurunから番組情報を取得する

`catalog sync`は、Mirakurun互換サービスからサービス一覧と番組一覧を一度取得し、DBへ保存するコマンドです。定期実行や自動再試行は行いません。

通常起動、DB操作、WebUIの表示ではMirakurunへ接続しません。このコマンドもチューナー操作、放送ストリームの取得、録画は行いません。

## 先にDBを作成する

実行ユーザーだけが読み書きできるデータ保存先を用意し、DBを最新の形式にします。

```console
sazanami-dvr db migrate --data-root <data-root>
sazanami-dvr db status  --data-root <data-root>
```

最後の出力が`state=CURRENT`であることを確認してください。別のプロセスが同じデータ保存先を使っている間は同期できません。

## 一度だけ同期する

```console
sazanami-dvr catalog sync \
  --data-root <data-root> \
  --provider mirakurun \
  --base-url <mirakurun-url>
```

`--base-url`には、自分で管理しているMirakurunのURLをスキーム、ホスト、ポートまで指定します。URLへ認証情報は埋め込めません。HTTPリダイレクト、環境変数によるプロキシ、TLS検証の無効化にも対応していません。

同期では次の順に読み取ります。

1. Mirakurunのバージョン
2. サービス一覧
3. 番組一覧

番組一覧から、番組名、概要、時刻、長さ、無料・有料に加えて、存在する場合は番組詳細、ジャンル、映像、音声を保存します。これらの追加情報がない番組も従来どおり利用できます。

バージョン情報を取得できなくても、サービス一覧と番組一覧が必要な条件を満たせば同期を続けます。未知のバージョンも、文字列だけを理由に拒否しません。

## 失敗しても前回の番組情報を残す

成功時は接続先を直接特定できないID、サービス数、番組数、所要時間、確認したバージョンを表示します。接続URL、データ保存先、番組名、番組説明、応答本文は表示しません。

サービス一覧と番組一覧のどちらかが不完全な場合、新しいカタログは公開しません。失敗した処理を`FAILED`として記録し、前回正常に完了したカタログをそのまま使います。

原因を調べる場合も、接続URL、認証情報、個人情報を含むパス、応答本文、番組情報を公開ログやIssueへ貼り付けないでください。

## 取得量と処理時間には上限がある

- 一度に処理する単位は最大256件
- 一回の同期はサービス4,096件、番組262,144件まで
- 応答本文はバージョン64 KiB、サービス16 MiB、番組256 MiBまで
- サービス取得は30秒、番組取得は5分、同期全体は10分まで

一覧は少量ずつ読み取り、応答全体を一つの配列としてメモリへ保持しません。TSIDを取得できないサービスは`PROVISIONAL`（情報不足）として保存します。

正当なカタログが上限を超えた場合は、件数と所要時間を確認してからコード側の上限を見直してください。実行時に上限を自動拡張する機能はありません。

## 取得結果をWebUIで確認する

同期完了後にWebUIを起動すると、現在時刻付近の番組を確認できます。

```console
sazanami-dvr ui serve --data-root <data-root> --listen 127.0.0.1:40800
```

WebUIは保存済みのカタログを表示するだけで、Mirakurunへの同期を始めません。Mirakurunが同じPCの40772番ポートを使っている場合は、上の例のように別のポートを指定してください。詳しくは[運用WebUIの利用手順](web-ui-operations.md)を参照してください。
