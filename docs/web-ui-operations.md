# 運用WebUIの使い方

WebUIでは、保存済みの番組情報、DBの状態、録画の状態を同じPCのブラウザーから確認できます。画面を開いても、番組情報の取得、チューナー操作、録画は始まりません。

初めて使う場合は「DBを用意する」と「WebUIを起動する」を読んでください。エラーが出た場合は末尾の一覧から原因を確認できます。

## DBを用意する

WebUIはDBを自動作成、更新しません。先に、実行ユーザーだけが読み書きできるデータ保存先を用意します。

```console
sazanami-dvr db status  --data-root <data-root>
sazanami-dvr db migrate --data-root <data-root>
sazanami-dvr db status  --data-root <data-root>
```

最後の出力が`state=CURRENT`であることを確認してください。別のプロセスが同じデータ保存先を使用している場合、WebUIは起動しません。

## WebUIを起動する

```console
sazanami-dvr ui serve --data-root <data-root>
```

ブラウザーで`http://127.0.0.1:40772/`を開きます。Mirakurunなどが40772番ポートを使っている場合は、別のポートを指定します。

```console
sazanami-dvr ui serve --data-root <data-root> --listen 127.0.0.1:40800
```

停止するには`SIGINT`または`SIGTERM`を送ります。待受先には`127.0.0.1`または`::1`だけを指定できます。`0.0.0.0`、LAN向けアドレス、`localhost`、ポート0は指定できません。

認証、TLS、リバースプロキシには対応していません。LANやインターネットへ直接公開しないでください。

## 画面で確認できること

- **概要:** DBの形式、取得元の数、短縮したビルド元コミット
- **番組表:** 最後に取得を完了した番組。標準では現在の3時間前から24時間後まで、最大256件
- **設定:** 現在の処理上限
- **操作:** 整合性検査付きのオンラインバックアップ

番組時刻はAsia/Tokyoで表示します。256件を超えた場合は打ち切ったことを画面に表示します。番組説明、接続先URL、データ保存先、ホスト名、利用者名、認証情報は画面へ渡しません。

## 画面からバックアップを作成する

「バックアップを作成」を押すと、SQLiteのオンラインバックアップを一件作成します。成功画面にはバックアップID、完了状態、DBの形式だけを表示します。

同時に二件は作成できません。復元、古いバックアップの削除、DBの更新、サービスの再起動も画面からは行いません。復元が必要な場合はWebUIを停止し、[カタログDBの運用と復旧](catalog-database-operations.md)に従ってください。

## エラーを調べる

| エラー | 確認すること |
|---|---|
| `current-database-required` | `db status`でDBの状態を確認する |
| `database-owner-unavailable` | 同じデータ保存先を使用中のプロセスがないか確認する |
| `loopback-listen-required` | `127.0.0.1`または`::1`と、1〜65,535のポートを指定する |
| `loopback-listen-failed` | 同じポートを使用中のプロセスがないか確認する |
| `product-commit-unavailable` | Gitのコミット情報を含む正式なビルドを使う |
| `backup-busy` | 先のバックアップが完了してから再実行する |

ロックファイルを手動で削除しないでください。原因を調べる場合も、認証情報、個人情報を含むパス、番組情報を公開ログやIssueへ貼り付けないでください。
