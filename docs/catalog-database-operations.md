# カタログDBの運用と復旧

この文書は、番組カタログを保存するSQLiteデータベースの作成、更新、バックアップ、復元方法を説明します。これらのコマンドはMirakurun、KonomiTV、チューナー、放送ストリームへ接続しません。

初めて使う場合は「DBを作成する」まで読んでください。障害から戻す場合は「バックアップから復元する」と「中断した復元を再開する」を参照してください。

## 操作前にSazanami DVRを停止する

- データ保存先には、実行ユーザーだけが読み書きできる絶対パスのディレクトリを指定する
- NFSやSMBなどの共有ファイルシステムへDBを置かない
- `db migrate`、`db restore`、`db recover`の前に、同じDBを使うプロセスをすべて停止する
- ロックファイルを手動で削除しない

DBを使用中のプロセスがある場合、変更や復元は失敗します。標準出力には状態とIDだけを表示し、データ保存先の実パスは表示しません。

## DBを作成する

Sazanami DVRは起動時にDBを自動更新しません。初回は次の順に実行します。

```console
sazanami-dvr db status --data-root <data-root>
sazanami-dvr db migrate --data-root <data-root>
sazanami-dvr db status --data-root <data-root>
```

初回の状態は`EMPTY`から`CURRENT`へ変わります。`FUTURE`、`DRIFTED`、`GAPPED`、`UNVERSIONED_NONEMPTY`、`UNREADABLE`のいずれかが表示された場合は、そのまま変更を続けないでください。チェックサムを無視して強制更新する機能はありません。

古い形式から更新する場合は、検証済みのバックアップを自動作成してからDBを変更します。途中で失敗した場合、DBの形式は更新前のままです。

v0.0.8では、自動予約条件と、その条件から作った予約の重複防止記録を保存するため、DB形式を第5版へ更新します。v0.0.7以前のDBを使う場合は、Sazanami DVRを停止してからv0.0.8の`db migrate`を一度実行してください。

v0.0.12では、番組詳細、ジャンル、映像、音声を保存するため、DB形式を第6版へ更新します。既存の番組情報は書き換えず、追加情報の保存欄は空のまま引き継ぎます。v0.0.11以前から更新する場合も、Sazanami DVRを停止してから`db migrate`を一度実行してください。

v0.0.20では、SQLiteのWALとSHMを利用者の`umask`にかかわらず0600へ揃えます。DB形式は第9版のままです。v0.0.19で更新前バックアップの復元が`sqlite: invalid database sidecar`になった場合は、DBを使用するプロセスを止めてv0.0.20へ更新し、同じ復元操作を最初からやり直してください。失敗した復元操作が残っているデータ保存先では、新しい復元を始めず、表示された操作IDで`db recover`を実行します。

v0.0.21では、予約ごとの字幕・データ放送設定を保存するため、DB形式を第10版へ更新します。v0.0.20以前の予約は、字幕あり、データ放送なしの既定設定として引き継ぎます。更新前バックアップから第9版へ復元する場合は、Sazanami DVRを停止し、v0.0.20の実行ファイルとバックアップDBを一緒に戻してください。

## バックアップを作成する

```console
sazanami-dvr db backup --data-root <data-root>
```

成功すると、`backup_id=<uuid> state=complete schema=<version>`を表示します。バックアップは次の順に作成されます。

1. SQLiteのオンラインバックアップ機能でDBを複製する
2. DBの整合性と外部キーを検査する
3. SHA-256とファイルサイズを記録する
4. DB本体を確定した後、最後に管理情報を確定する

作成前に、現在のDBサイズに64 MiBを加えた空き容量があるか確認します。ただし、この容量は成功を保証するものではありません。書き込みや同期に失敗した場合は、未完成のバックアップとして扱います。

管理情報がないDB、途中ファイル、ハッシュが一致しないDBは復元に使いません。古いバックアップや途中ファイルは自動削除しないため、内容を確認してから別途管理してください。

## バックアップから復元する

Sazanami DVRを停止してから実行します。

```console
sazanami-dvr db restore --data-root <data-root> --backup-id <uuid>
```

復元前と配置後の両方で、ハッシュ、DB形式、整合性、外部キーを確認します。元のDB、WAL、SHMは退避し、自動削除しません。成功すると`phase=COMMITTED`を表示します。

復元後は`db status`を実行し、通常起動する前に`state=CURRENT`であることを確認してください。

## 中断した復元を再開する

復元が途中で止まった場合は、通常起動せず、表示された操作IDを指定します。

```console
sazanami-dvr db recover --data-root <data-root> --operation-id <uuid>
```

元のDBを安全に特定できる場合は変更前へ戻し、新しいDBの配置を安全に続けられる場合は復元を再開します。どちらを正本にするか判断できない場合は`FAILED_NEEDS_OPERATOR`で停止し、ファイルを自動削除しません。

`COMMITTED`または`ROLLED_BACK`になるまで、新しい復元や通常の書き込み処理を始めないでください。

## 古いバージョンへ戻す

新しい形式のDBを古いバイナリで直接開かないでください。更新前に作成されたバックアップを復元してから、古いバイナリを起動します。SQLiteドライバーだけを戻して互換性があると判断することもできません。

## 現在の制限

- 古いバックアップと退避ファイルは自動削除しない
- アプリケーション独自の暗号化、署名、外部ストレージへの転送は行わない
- 同じDBを複数のプロセスやホストから共有しない
