# Komorebi向け複数チャンネル番組表仕様 v1

- Status: Accepted
- Accepted date: 2026-08-10
- Decision owner: Project owner
- Delegated reviewer: Codex
- Requirement prefix: `KMPG`
- Target client: Komorebi 1.1.0-beta6 / `41916c63cdf53cc62643333f630bb1095c14a298`
- Related: ADR-0026、ADR-0044、Plan 0059

## 目的

KomorebiがCtrlCmd 1029で複数チャンネルをまとめて指定したとき、Sazanamiの完成済み番組表から対応するサービスと番組を返す。KonomiTVの全件指定と既存の1チャンネル指定は維持する。

## 要件

### KMPG-001: 受け付ける形式

要求本文はCtrlCmdの64ビット整数ベクター一つとする。KonomiTVの既存全件指定4要素は従来どおり受け付ける。それ以外は、1件以上4,096件以下のサービス指定と、共通の開始・終了時刻を次の順で受け付ける。

```text
[0, serviceKey1, 0, serviceKey2, ... , startFileTime, endFileTime]
```

サービス数を`N`とした本文長は`24 + 16N`バイトであり、最大65,560バイトとする。整数要素数は4以上の偶数でなければならない。

### KMPG-002: サービス指定

各組の先頭は0、サービスキーは0以上`0xFFFFFFFFFFFF`以下とする。サービスキーは`ONID << 32 | TSID << 16 | SID`である。同じサービスキーを一要求へ重複して指定しない。形式不正、範囲外、重複は番組表を読む前に安定した理由で拒否する。

完成済みsnapshotに存在しないサービスキーは結果へ含めない。他の有効なサービスと要求全体は失敗させない。

### KMPG-003: 時刻範囲

末尾2要素は全サービスに共通するFileTimeの開始と終了とする。開始は0以上で、開始より終了が大きくなければならない。番組の開始時刻が`startFileTime <= value < endFileTime`を満たす場合だけ返す。

### KMPG-004: 完成済み世代

要求開始時に固定した一つの完成済み番組表世代だけを読む。1029要求、Komorebiの画面表示、アプリ再起動を理由にMirakurun／mirakcへ接続しない。失敗した同期中は直前の完成済み世代を維持する。

### KMPG-005: 応答

指定されたサービスだけを、既存1029と同じServiceInfoとEventInfoで返す。応答順、番組の適格条件、詳細、ジャンル、映像、音声、文字列変換は変えない。要求順による重複や別の応答形式を追加しない。

### KMPG-006: 上限とメモリ

サービスは4,096件、番組は262,144件、応答本文は256 MiBを上限とする。既存の256件単位のDB読取り、二回走査、大きさの事前確定、逐次出力を維持する。番組全件または応答全体を一つの配列やバイト列へ保持しない。

### KMPG-007: 失敗

不正長、途中切断、長さ不一致、要素数不正、組の形式不正、重複、時刻不正、件数超過、生成中の世代差、取消し、期限切れ、書込み切断では、完全な成功ヘッダーを返さない。DB、完成済み番組表、予約、録画、録画ファイルを変更しない。

### KMPG-008: 互換性の維持

KonomiTVの全件指定、既存1チャンネル指定、未知1チャンネル、番組0件の結果を変えない。1021、1025、予約、録画、自動予約、録画済み情報、ライブ視聴、HTTP APIの形式を変えない。

### KMPG-009: 依存と版

実装はGo標準ライブラリと既存の依存ライブラリだけを使う。新しい依存ライブラリ、CGO、フレームワーク、ORM、コード生成、Java、Node／npm、外部プロセスを追加しない。製品版はv0.0.24とする。

### KMPG-010: 記録と表示

公開互換表は、Komorebi 1.1.0-beta6の複数チャンネル番組表を自動確認とAndroid上での確認に分けて示す。Android TV実機で確認していない結果を実機確認済みにしない。番組名、放送局名、接続先、利用者名、絶対パス、生の要求・応答、TS内容を通常ログ、Git、CI成果物、報告へ残さない。

## 必須テスト

- 1件、2件、4,096件、4,097件、0件、奇数要素、途中切断、長さ不足、末尾余り。
- 組の先頭が0以外、負のサービスキー、48ビットの上限を一つ超える値、重複、未知キー、要求順の違い。
- 開始0、通常範囲、境界一致、開始と終了の同値、逆転、負値、最大値。
- KonomiTV全件指定と既存1件指定のgolden回帰。
- 複数サービスで対象だけを返し、未知サービスを省き、同じ番組を重複させないこと。
- 256件ページ、4,096サービス、262,144番組、256 MiB、一件／1バイト超過、二回走査差、同時生成、取消し、期限切れ、書込み切断、全件配列なし。
- 1021、1025、予約、自動予約、録画、録画済み情報、ライブ、HTTPの既存テスト。
- `go test ./...`、実行順を変えるテスト、競合検出テスト、`go vet ./...`、`go mod verify`、`govulncheck ./...`、CGO無効のLinux／Darwin amd64／arm64ビルド、Hosted Ubuntu CI。

## 実験環境

公開Linux amd64配布物を許可済み実験環境へ導入する。公式Komorebi 1.1.0-beta6 APKをテレビ向け画面寸法のAndroid環境で起動し、Sazanamiへ直接接続する。アプリ再起動後にホーム、番組表、予約画面を開き、番組表に内容があり、応答ヘッダーの読取り失敗、接続拒否、致命的なエラーが0件であることを確認する。

Android TV実機またはAndroid TV system imageでない場合は、その環境差を明記する。番組名、放送局名、接続先、生ログ、生の要求・応答は保存しない。
