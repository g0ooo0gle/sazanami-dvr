# KonomiTV・Komorebi共通の予約変更成功応答仕様 v1

- Status: Accepted
- Version: 1
- Date: 2026-08-10
- Target product base: Sazanami DVR v0.0.24 / `cbc07305b4b0fd87a59d86edfd3e6c4d1e85951c`
- Target clients: KonomiTV v0.14.1 / `0a32188274b81c1e7bed642474b208bd2a543a6b`、Komorebi 1.1.0-beta6 / `41916c63cdf53cc62643333f630bb1095c14a298`

## 目的

単発予約の追加、変更、削除について、KonomiTVの既存動作を保ちながら、Komorebiが保存後の成功応答を正しく読めるようにする。

## 対象コマンド

| 操作 | CtrlCmd | 成功条件 |
|---|---:|---|
| 単発予約の追加 | 2013 | 予約と設定を一回のDB処理で保存した |
| 単発予約の変更 | 2015 | 対象の未完了予約を比較更新した |
| 予約の削除または録画中停止 | 1014 | 取消しまたは停止要求をDBへ確定した |

要求本文、入力検証、保存条件、予約状態は既存仕様を変更しない。

## 成功応答

三つのコマンドは、成功時に次のフレームを返す。

| 項目 | 値 |
|---|---|
| result code | 32ビット符号付きlittle-endian整数`1` |
| response body length | 4 byte |
| response body | 32ビット符号付きlittle-endian整数`1` |

フレーム全体の固定byte列は次のとおりである。

```text
01 00 00 00 04 00 00 00 01 00 00 00
```

2013、2015、1014で同じ出力関数を使う。本文の`1`をversion、予約番号、件数として扱わない。

## 失敗応答

入力不正、未対応設定、対象なし、DB失敗は、既存どおりresult code `0`、本文長`0`とする。内部理由、予約内容、pathを本文へ含めない。

応答のheaderまたは本文を書けなかった場合、呼出し元へ安定した書込み失敗を返す。既にDBへ確定した操作は巻き戻さず、自動再実行しない。

## 互換条件

- KonomiTV v0.14.1は外側のresult codeで成功を判断し、4バイト本文があっても既存操作を継続できる。
- Komorebi 1.1.0-beta6は本文を32ビット整数として読み、値`1`を成功と判断できる。
- クライアント名、接続元、User-Agentによる応答分岐を作らない。
- 2011のversion `5`と一覧形式は変更しない。

## 処理と再送

保存処理は、成功応答の生成前に一度だけ行う。応答書込み失敗やクライアント切断を理由に、2013、2015、1014をSazanami内部で再実行しない。

クライアントが結果を読めなかった場合、2011で現在状態を確認できる。2013を無条件に再送して重複予約を作る動作は、互換動作として提供しない。

## 必須テスト

- 2013、2015、1014の成功フレームが、上記12 byteと完全一致する。
- 32ビット整数として本文を読むKomorebi向け契約テスト。
- 本文を利用せずresult codeだけを確認するKonomiTV向け回帰テスト。
- 各コマンドの入力不正、対象なし、保存失敗がresult code `0`、空本文になる。
- 応答header切断、本文1～3 byteでの切断、context取消しで、保存処理が二度呼ばれない。
- 2013、2015、1014、2011、録画中停止、予約設定、DB、診断の既存テスト。
- ローカルfull、順序変更、race、vet、依存検証、既知脆弱性検査、CGO無効の主要4環境ビルド、Hosted Ubuntu CI。

## 実環境確認

公開Linux amd64配布物を許可済み実験環境へ導入する。KonomiTV v0.14.1のHTTP APIと公式Komorebi 1.1.0-beta6から、それぞれ将来番組の予約追加、設定変更、削除を一巡する。

操作ごとに保存状態を読み戻し、画面上の失敗、応答解析例外、接続拒否、致命的エラーが0件であることを確認する。試験予約は確認後に削除する。件数と成否だけを記録し、番組名、放送局名、接続先、利用者名、絶対path、生の要求・応答を残さない。
