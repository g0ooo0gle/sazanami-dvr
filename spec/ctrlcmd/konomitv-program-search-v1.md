# KonomiTV番組検索仕様 v1

- Status: Accepted
- Date: 2026-08-09
- Requirement prefix: `SEARCH`
- Related: ADR-0026、ADR-0035、Plan 0048

## 目的

KonomiTV v0.14.1の番組検索画面が使うCtrlCmd 1025を、最後に正常取得できた番組表に対する上限付き検索として提供する。

## 要件

### SEARCH-001: 対応する要求と応答

録画用CtrlCmd待受は1025を受け付ける。要求本文は従来形式の`vector<SearchKeyInfo>`であり、KonomiTVが送る一条件だけを受理する。応答は従来形式の`vector<EventInfo>`とする。版番号を付けるCmd2形式へ読み替えない。

### SEARCH-002: 条件の構造

`SearchKeyInfo`は、構造長、検索語、除外語、正規表現、番組名限定、ジャンル配列、曜日・時刻配列、放送局配列、映像配列、音声配列、あいまい検索、ジャンル除外、日時除外、無料・有料の順に厳密に読む。自動予約だけが持つ録画済み確認の3項目を1025へ要求しない。構造の不足、余分な末尾、未知flag、範囲外の値は失敗にする。

文字列はUTF-8換算4,096 bytes以下、放送局4,096件以下、ジャンル256件以下、日時64件以下、映像と音声は各256件以下とする。要求全体は既存のCtrlCmd本文上限を超えない。

### SEARCH-003: 検索語

検索語は番組名と説明を対象にする。番組名限定なら説明を含めない。通常検索は空白で区切った語をすべて含む番組だけを一致とする。除外語は一語でも含む番組を除外する。大文字小文字を区別しない指定ではUnicodeの小文字化後に比較する。

正規表現はGo標準ライブラリを使う。不正な正規表現は空一覧へ丸めず、`program-search-regexp-invalid`で失敗する。

KonomiTVが除外語の先頭へ`:note:`形式で入れるメモは検索条件ではない。妥当なエスケープを読んでメモ部分だけを外し、後続の除外語を判定に使う。不正なメモ表現は`program-search-note-invalid`で失敗する。検索語、除外語、メモは保存または出力しない。

### SEARCH-004: 放送局

放送局配列はONID、TSID、SIDを詰めた48 bit値として読む。空配列は検索対象なしとする。各値は同じ完成済みチャンネルスナップショットに一意に存在し、検索対象として有効な放送局だけを選ぶ。未知または重複する値は結果へ含めない。

### SEARCH-005: 曜日、時刻、番組長

曜日は0を日曜、6を土曜とし、時刻はAsia/Tokyoで判定する。開始を含み、終了を含まない。週末をまたぐ範囲を扱い、開始と終了が同じ範囲は全時間とする。日時除外は一致結果を反転する。

番組長は検索語に埋め込まれた既存CtrlCmd表現から最小・最大分を読む。0は下限または上限なしとする。両方が1以上で最小が最大を超える要求は失敗にする。

### SEARCH-006: 無料・有料

0は指定なし、1は無料だけ、2は有料だけとする。無料状態が不明な番組は、1または2を指定した検索結果へ含めない。

### SEARCH-007: 無効条件と未対応条件

無効prefixを持つ条件は正常な空一覧を返す。ジャンル、映像、音声、あいまい検索を要求した場合は、条件を無視せず`program-search-condition-unavailable`で失敗する。ジャンル除外はジャンル配列が空でも未対応とする。

### SEARCH-008: 完成済み世代

要求開始時に現在の完成済み番組表世代を一度だけ固定し、応答完了まで同じ世代を使う。通常の検索ではMirakurun／mirakcへ接続しない。番組表更新が失敗中でも、直前の完成済み世代を検索する。

### SEARCH-009: 上限付き二回走査

番組は256件ずつ読み、最初の走査で一致件数と応答サイズを測る。二回目は同じ条件で一致番組を逐次出力する。検索結果全体と番組表全体をメモリへ保持しない。

結果は262,144件以下、応答本文は256 MiB以下、同時生成は一件とする。一件超過、応答超過、同時要求はそれぞれ安定した理由で失敗する。二回の件数、順序、内容が変わった場合は成功応答にしない。

### SEARCH-010: 番組情報

応答の`EventInfo`は1029と同じ既存変換を使う。ONID、TSID、SID、EID、開始時刻、長さ、番組名、説明、無料状態を返す。必要値が不正または不足する番組は両走査で同じように除外する。

### SEARCH-011: 取消しと失敗

context取消し、期限、DB読出し、応答書込み、世代差は成功へ丸めない。失敗は予約、録画、完成済み番組表、録画ファイルを変更しない。検索条件や番組情報をエラーへ含めない。

### SEARCH-012: 依存と公開表示

実装はGo標準ライブラリだけを使い、新しい依存、CGO、framework、ORM、code generation、外部processを追加しない。DB schemaは変更しない。公開互換表は通常検索と、未対応のジャンル・あいまい検索を分けて表示する。製品versionは0.0.11とする。

## 必須テスト

- KonomiTV固定版の一条件byte列、空条件、無効条件、空放送局、未知放送局。
- キーワードのAND、除外、メモ、大文字小文字、正規表現、番組名限定、不正正規表現。
- 放送局、曜日、週またぎ、日時除外、最小・最大番組長、無料・有料、不明状態。
- あいまい、ジャンル、ジャンル除外、映像、音声が未対応として失敗すること。
- 構造、文字列、配列、整数、flag、末尾、本文、個数の各上限と一件超過。
- 256件境界、262,144件と一件超過、256 MiBと一byte超過、空結果。
- 二回走査の件数・順序差、書込み失敗、取消し、同時2件目、DB失敗。
- 通常command、番組表、予約、自動予約、ライブ視聴の回帰。
- `go test ./...`、shuffle、race、vet、`go mod verify`、`govulncheck ./...`、CGOを使わないLinux／Darwin amd64／arm64 build、Hosted Ubuntu CI。

## 実験環境

公開Linux amd64配布物を隔離data rootへ導入し、KonomiTV v0.14.1の検索画面で、通常検索、除外、番組名限定、放送局、日時、番組長、無料・有料を確認する。検索語、番組名、放送局、宅内識別子、生の要求と応答は記録しない。ジャンルとあいまい検索は未対応表示と実際の結果が一致することを確認する。
