# 利用者による録画中停止仕様 第1版

- Status: Accepted
- Accepted date: 2026-08-09
- Decision owner: Project owner
- Delegated reviewer: Codex
- Related decision: [`../../docs/adr/0037-user-stopped-recording-publication.md`](../../docs/adr/0037-user-stopped-recording-publication.md)

## 目的

KonomiTVまたは対応クライアントから一件の録画を停止し、停止時点までに有用なTSがあれば部分録画として再生できる状態へ安全に確定する。

## 要件

| ID | 要件 |
|---|---|
| `USTOP-001` | CtrlCmd 1014は一件の予約番号を受け、録画開始前の取消しまたは録画中の停止要求を行う。 |
| `USTOP-002` | 録画中の停止要求はSQLiteへ一度だけ保存してから成功応答を返す。DB更新失敗時は録画を止めず失敗応答にする。 |
| `USTOP-003` | 停止できる録画状態は`CLAIMED`、`STARTING`、`RECORDING`とし、`FINALIZING`以降を中断しない。 |
| `USTOP-004` | 一件の停止は同じ内部予約IDの実行だけを取り消し、他の録画と常駐処理へ伝播させない。 |
| `USTOP-005` | 実行中通知の登録数は最大8件とし、追加goroutine、キュー、プロバイダー接続を作らない。 |
| `USTOP-006` | 録画処理は開始前と5秒以下の進捗保存時に、DBの停止要求を確認する。通知を受けた場合は待たずに同じ終了処理へ入る。 |
| `USTOP-007` | 停止時に188バイト以上を保存していれば、同期、完成名の上書きしない公開、ディレクトリ同期、部分名除去を行う。 |
| `USTOP-008` | 公開できた録画は`PARTIAL/USER_REQUESTED_STOP`、ファイル利用状態`FINAL`とし、正常完了とは区別して再生可能にする。 |
| `USTOP-009` | 188バイト未満は完成名へ公開せず、`CANCELLED/USER_REQUESTED_STOP`と実際のファイル利用状態を保存する。 |
| `USTOP-010` | 完成処理の予定状態と理由をDBへ保存し、再起動後も利用者停止を正常完了へ変更しない。 |
| `USTOP-011` | 完成名の衝突、バイト数不一致、安全でないファイル、DBまたはファイル操作失敗を成功へ丸めず、既存ファイルを上書きしない。 |
| `USTOP-012` | 予約番号、内部ID、番組情報、接続先、絶対パス、生の要求と応答を通常ログへ出さない。 |

## CtrlCmd 1014

要求と応答の通信形式、ベクター件数一件、本文上限、版に依存しない従来形式は既存仕様を維持する。不正な構造、0以下の番号、複数番号、一バイト超過は失敗とし、DBや実行中録画を変更しない。

次のいずれかをSQLiteトランザクションで確定した場合だけ成功応答を返す。

- 録画処理がない`ACTIVE`予約を`FINISHED/CANCELLED_BY_USER`へ進めた。
- `CLAIMED`、`STARTING`、`RECORDING`の録画処理へ停止要求時刻を初めて保存した。
- 同じ録画処理に同じ利用者停止要求が既に保存済みで、まだ終端していない。

存在しない番号、終了済み予約、通常の完成処理へ入った録画は失敗応答とする。内部理由を応答本文へ含めない。

## DBと実行中通知

停止要求は録画処理へUTCミリ秒で保存する。未来時刻、負値、録画作成より前の時刻を受け付けない。終了状態と停止要求の組合せはCHECK制約とrepository検証で確認する。

実行中登録表は内部予約IDをキーにし、値としてその録画だけの取消し関数を持つ。同じIDの二重登録、8件超過、nil取消し関数は失敗させる。登録解除は録画goroutineの終了時に必ず行い、解除後の取消しは何もしない。

1014はDBのコミット後に登録表へ通知する。登録表に対象がなくても1014を失敗させない。録画処理はストリームを開く前と進捗保存時にDBを読み、停止要求を見つけたら通知と同じ終了処理へ入る。

## file公開と終了状態

停止通知またはDB要求を見つけた録画は、再接続を行わず、現在のleaseを取り消して閉じる。部分ファイルのバイト数を進捗として保存し、同期して閉じる。

188バイト以上なら次の順で公開する。

1. 最終状態`PARTIAL`、理由`USER_REQUESTED_STOP`、バイト数、完成処理トークンをDBへ保存する。
2. 既存の上書きしないリンクで完成名を公開する。
3. 公開をDBへ記録し、ディレクトリを同期する。
4. 部分名を除き、再度ディレクトリを同期する。
5. ファイル状態を`FINAL`、録画処理を`PARTIAL/USER_REQUESTED_STOP`、予約を終了状態へ進める。

完成処理中も、完成済み録画と同じファイルとディレクトリの永続化条件を守る。状態`PARTIAL`は内容が予定終了前であることを示し、ファイル状態`FINAL`は検証済みの完成名から読み出せることを示す。

188バイト未満は完成処理を始めない。部分ファイルが存在すれば同期して閉じ、ファイル状態`PARTIAL`とする。部分ファイルを作る前なら`MISSING`とする。録画処理は`CANCELLED/USER_REQUESTED_STOP`へ進める。

## 再生公開

CtrlCmd録画一覧、録画一件取得、Native REST、HTTP Range再生は、次をすべて満たす利用者停止録画を再生可能とする。

- 状態が`PARTIAL`。
- 理由が`USER_REQUESTED_STOP`。
- 188バイト以上で、開始時刻と終了時刻が1秒以上離れている。
- segmentが`FINALIZED`、ファイル状態が`FINAL`。
- ファイル同期、完成名公開、ディレクトリ同期の証拠が揃っている。

通常の部分録画、完成処理途中、ファイル欠落、整合性不一致は再生可能にしない。公開APIは部分録画であることと停止理由を返す。

## 再起動と競合

`FINALIZING`の復旧はDBに保存した予定状態と理由を読む。通常録画は既存の正常完了へ、利用者停止は`PARTIAL/USER_REQUESTED_STOP`へ進める。予定値が欠落、不正、相互に矛盾する場合は正常完了へ推測せず、整合性失敗にする。

1014と予定終了が競合した場合は、SQLiteの比較更新で先に確定した側だけを採用する。停止要求が先なら利用者停止、`FINALIZING`遷移が先なら通常完成を継続する。両方を成功扱いにしない。

プロセス終了と利用者停止が競合した場合、DBに利用者停止要求が確定済みなら`USER_REQUESTED_STOP`を維持する。確定前なら既存の`PROCESS_SHUTDOWN`とする。

## 固定上限

| 項目 | 値 |
|---|---:|
| 1014の予約番号 | 1件 |
| 実行中登録 | 8件以下 |
| 停止要求時刻 | 1件、上書きなし |
| 追加goroutine | 0 |
| 追加キュー | 0 |
| 停止後の再接続 | 0回 |
| 再生可能にする最小バイト数 | 188バイト |

既存のCtrlCmd本文、deadline、ストリームバッファ、ファイルパス、shutdown、同時録画上限を維持する。

## 必須テスト

### 通信と状態

- 固定KonomiTVの1014 byte列、録画開始前取消し、`CLAIMED`、`STARTING`、`RECORDING`の停止。
- 存在しない番号、0、負数、複数番号、途中で切れた要求、一バイト超過、接続先切断、要求取消し。
- 同じ停止要求の再送、並行1014、停止と`FINALIZING`の競合。
- DBのコミット前は実行を止めず、コミット後の通知失敗はDB確認で停止する。
- 一件を止めても最大7件の他録画、番組表更新、ライブ視聴が継続する。

### ファイルと再生

- 0、187、188バイト、複数chunk、大きい録画。
- sync、close、link、ディレクトリ同期、部分名除去、DB更新の各失敗。
- 完成名衝突で既存ファイルを変更しない。
- 利用者停止の部分録画だけをCtrlCmd、Native REST、HTTP Rangeで読み出せる。
- 通信障害、プロセス終了、容量不足による部分録画は再生一覧へ出さない。

### 再起動

- 停止要求保存後、ファイルを閉じた後、完成処理開始後、リンク後、各ディレクトリ同期後、DB終端前の再起動。
- 全地点で同じバイト数と`PARTIAL/USER_REQUESTED_STOP`へ収束する。
- ファイル欠落、バイト数違い、ハードリンク不一致、安全でないファイルは成功にしない。
- 同じ復旧を二回行ってもファイル、履歴、終了理由を増やさない。

### 品質と実験環境

- full、shuffle、race、vet、`go mod verify`、`govulncheck`、CGO無効のLinux／Darwin amd64／arm64 build、Hosted Ubuntu CI。
- KonomiTV v0.14.1から録画中の一件を停止し、一覧化と再生開始を確認する。
- 停止した録画と同時に動く別録画が完了することを確認する。
- 宅内識別情報と番組情報を残さず、件数、バイト数、秒数、終了理由だけを記録する。

## 対象外

- 停止後のTS修復、欠損補完、再エンコード、複数file結合。
- 利用者停止以外の部分録画を自動で再生可能にすること。
- 録画済みファイルの削除、保持期間、自動削除。
- 録画設定、保存先、ファイル名規則の変更。
