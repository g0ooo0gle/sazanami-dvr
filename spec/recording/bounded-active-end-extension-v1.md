# 録画中の終了時刻延長仕様 第1版

- Status: Accepted
- Date: 2026-08-09
- Related ADR: ADR-0030

## 目的

録画中に同じ番組の放送時間が延びた場合、固定上限内で録画の終了時刻だけを延ばす。

## 要件

| ID | 要件 |
|---|---|
| `AEE-001` | 追従ありの有効予約と、同じMirakurun内の検証済み後継番組だけを対象にする。 |
| `AEE-002` | 後継番組の開始時刻が予約と同じで、終了時刻が後ろへ動く場合だけ更新する。 |
| `AEE-003` | 一件だけの録画処理が`CLAIMED`、`STARTING`、`RECORDING`のいずれかである場合だけ更新する。 |
| `AEE-004` | 予約revision、放送時間、録画処理の予定終了時刻を一つの比較更新で保存する。 |
| `AEE-005` | 実行中の録画は5秒ごとの進捗保存で予定終了時刻を読み直す。 |
| `AEE-006` | 録画開始から12時間と、確保時の終了時刻の遅い方を絶対上限とする。 |
| `AEE-007` | 短縮、開始時刻変更、別番組、完了処理中、競合時は以前の終了時刻を維持する。 |
| `AEE-008` | 番組表の既定更新間隔を5分とし、既存の取得上限と失敗時の完成番組表維持を守る。 |
| `AEE-009` | 新しいschema、依存、監視goroutine、queue、接続先、秘密情報を追加しない。 |

## DB更新

既存の予約追従処理を拡張する。録画処理がない場合はv0.0.5の録画開始前追従を行う。録画処理が一件ある場合は、次を同じtransactionで再確認する。

- 予約ID、version、revision、`ACTIVE`、`requested_follow=1`。
- 録画処理の予約ID、現在の予定終了時刻、状態。
- 最新の完成済み番組表に後継revisionが存在すること。
- 後継の開始時刻が予約開始時刻と同じであること。
- 後継の終了時刻が現在の予定終了時刻より後であること。

条件を満たす場合だけ、予約の`program_revision_id`、`duration_seconds`、`version`、`updated_at_utc_ms`と、録画処理の`planned_end_utc_ms`、`state_version`、`updated_at_utc_ms`を更新する。heartbeatとbyte数は変えない。

## 録画処理

進捗保存は、保存後の`planned_end_utc_ms`を返す。録画処理は戻り値が現在の終了時刻以上で絶対上限以下の場合だけ、メモリ上の終了時刻を更新する。以前より短い値、不正時刻、上限超過、DBエラーは成功扱いにしない。

stream用contextは絶対上限で作る。データ受信loopはメモリ上の終了時刻で止める。再接続の残り時間判定も更新後の終了時刻を使う。親contextの取消しは常に優先する。

## 番組表更新

既定間隔を5分にする。最小5分、最大24時間、起動直後の一回、同時一回、失敗時に以前の完成番組表を維持する契約は変えない。利用者が明示した間隔は変更しない。

## 出力

既存の予約追従集計と番組表更新集計だけを使う。予約ID、番組名、接続先、絶対path、生の応答を追加しない。

## 必須test

- `CLAIMED`、`STARTING`、`RECORDING`での延長。
- 録画処理なしの従来追従、`FINALIZING`、terminal、複数処理、競合。
- 同じ終了、短縮、開始時刻変更、別instance、未検証revision、12時間境界と一件超過。
- 進捗保存で終了時刻を更新し、元の終了時刻を越えて録画を続ける。
- 不正な戻り値、DB失敗、親cancel、再接続中、終了直前の競合。
- 既定5分、明示間隔、失敗した番組表世代、再起動。
- 通常、順序変更、競合検出、静的検査、既知脆弱性検査、CGO無効4環境build、Hosted Ubuntu CI。

## 実験環境

公開候補で番組表、予約、録画、録画済み一覧、再生開始を回帰確認する。安全に実放送の延長を観測できない場合は、`NOT RUN: no live extension observed`と記録する。

## 対象外

短縮、開始時刻変更、retune、event relay、TS解析、複数同時録画、自動予約。
