# 自動予約の番組条件共通化仕様 v1

- Status: Accepted
- Date: 2026-08-10
- Requirements: `APCM-001`～`APCM-012`
- Related ADR: ADR-0046

## 目的

番組検索1025で確認済みの条件判定を自動予約でも使い、KonomiTVとKomorebiの主要な検索条件から予約を作れるようにする。

## 要件

### APCM-001: 共通判定

通信形式に依存しないcoreの判定器は、`SearchCondition`を一度準備し、完成済み番組表の`CurrentProgram`一件を判定する。番組検索1025と自動予約は同じ判定器を使う。CtrlCmd codec、SQL、HTTP、録画設定を共通判定へ持ち込まない。

### APCM-002: 文字列

番組名、概要、詳細を検索対象とする。番組名限定では番組名だけを使う。通常検索の空白区切りAND、除外語、大文字小文字、正規表現、あいまい検索は、Acceptedの番組詳細・全検索条件仕様と同じ意味にする。除外語と正規表現へあいまい検索を適用しない。

### APCM-003: Metadata

ジャンル、ジャンル除外、映像、音声は、完成済み番組表に保存されたmetadataだけで判定する。条件があり必要なmetadataがない番組は一致させない。ジャンル情報なしを表す`0xFF / 0xFF`は、既存番組検索と同じ扱いにする。

### APCM-004: 時刻、長さ、無料状態

曜日と時刻はAsia/Tokyoで、開始を含み終了を含まない。週またぎ、同時刻の全時間、日時除外を既存番組検索と同じように扱う。番組長は分単位、無料・有料は既知の状態だけを一致させる。開始時刻、長さ、無料状態が不足する番組を推測で一致させない。

### APCM-005: 放送サービス

放送サービスは共通判定器の外で照合する。番組検索は要求で固定した対象サービスだけを走査する。自動予約は既存の番組から予約要求への変換後に、ONID、TSID、SIDを照合する。空のサービス一覧は既存どおり全サービスを表す。

### APCM-006: 準備失敗

正規表現は規則または検索要求ごとに一度だけcompileする。不正な正規表現を含む1025は`program-search-regexp-invalid`で失敗する。自動予約では該当規則を判定不能として数え、その規則から予約を作らず、ほかの規則を続ける。検索語や正規表現をerrorへ含めない。

### APCM-007: 自動予約で有効にする条件

ジャンル、ジャンル除外、あいまい検索、映像、音声を、自動予約の判定可能条件へ加える。これらを含む既存規則も、次の正常な番組表同期後から追加操作なしで評価する。

### APCM-008: 引き続き判定不能とする条件

録画済み番組名照合を要求する規則は、保存と一覧の対象にはするが予約を作らない。録画後の電源操作、再起動、継続録画、強制tuner、ワンセグ別出力など、既存録画処理が安全に適用できない設定も従来どおり判定不能とする。対応する条件だけを無視して広く一致させない。

### APCM-009: 評価順と重複防止

完成済み番組表の公開と時刻追従が成功した後だけ一回評価する。CtrlCmd番号が小さい規則を先に評価し、同じ番組へ複数予約を作らない。同期二回、再起動、取消済みまたは完了済み予約がある場合の既存重複防止を維持する。

### APCM-010: 上限とメモリ

規則128件、番組32,768件、比較4,194,304回、新規予約256件、番組metadata 256 KiB、検索語4 KiBの上限を変えない。判定器は番組表全体や検索結果全体を保持しない。あいまい検索は検索語の長さに比例する2行の整数配列だけを使う。新しい永続cache、queue、goroutine、workerを追加しない。

### APCM-011: 回帰と公開表示

1025の要求、応答、失敗理由、二回走査、件数、本文、同時実行の意味を変えない。予約、録画、録画済み一覧、直接ライブも回帰させない。公開互換表は自動予約の各条件を、保存、評価、自動test、実環境確認に分けて表示する。製品versionは0.0.26とする。

### APCM-012: 依存と秘密情報

実装はGo標準ライブラリと既存依存だけを使う。新しいdependency、CGO、framework、ORM、code generation、Node／npm、外部processを追加しない。検索語、番組名、詳細、ジャンル名、放送局、接続先、生の要求・応答を通常ログ、Git、実験結果へ記録しない。

## 必須テスト

- 通常文字列AND、除外、大文字小文字、正規表現、番組名限定、詳細、不正正規表現。
- あいまい検索の完全一致、一文字差、挿入、削除、25%境界、一件超過、全角ASCII、かな、半角カナ、濁点、case、除外語との分離。
- ジャンルの大分類、中分類全体、拡張、情報なし、除外、映像、音声、metadataなし。
- 曜日、週またぎ、日時除外、最小・最大番組長、無料・有料、不明状態。
- 自動予約の放送サービス、空サービス、録画済み番組名照合、未対応録画設定。
- 1025と自動予約へ同じ条件と番組を与えたとき、サービス照合を除く判定結果が一致すること。
- 同期二回、再起動、二規則一致、取消済み、完了済み、規則・番組・比較・新規予約の各上限と一件超過。
- DB失敗、予約作成失敗、ID生成失敗、取消し、途中停止で以前の完成済み番組表と既存予約を維持すること。
- 1025の全既存契約、二回走査、256件ページ、262,144件、256 MiB、全件配列なしを回帰確認すること。
- `go test -count=1 ./...`、順序変更、競合検出、`go vet ./...`、`go mod verify`、`govulncheck ./...`、CGO無効のLinux／Darwin amd64／arm64 build、Hosted Ubuntu CI。

## 実験環境

公開Linux amd64配布物を隔離data rootへ導入する。固定版KonomiTVから、将来番組の実metadataに基づく一時規則を追加し、番組表同期後に一件以上の予約が作られることを確認する。同じ同期の再実行で予約が増えないこと、再起動後に規則と予約を読み戻せることも確認する。

試験後は一時規則と不要な予約を削除する。条件値、番組名、番組詳細、ジャンル名、放送局、接続先、利用者名、絶対path、生の要求・応答を記録しない。KonomiTV画面または実番組が条件を提供しない項目は、未実施として条件ごとに明記する。
