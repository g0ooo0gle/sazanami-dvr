# 基本録画設定仕様 第1版

- Status: Accepted
- Accepted date: 2026-08-09
- Decision owner: Project owner
- Delegated reviewer: Codex
- Related decision: [`../../docs/adr/0039-effective-basic-recording-settings.md`](../../docs/adr/0039-effective-basic-recording-settings.md)

## 目的

KonomiTVから予約の有効状態、優先度、開始・終了の余白を読み書きし、表示した設定と実際の録画予定時刻を一致させる。

## 要件

| ID | 要件 |
|---|---|
| `BSET-001` | 2013と2015は、有効な指定サービス録画`rec_mode=1`と無効な指定サービス録画`rec_mode=5`を受け付ける。 |
| `BSET-002` | 優先度は1～5、番組追従は従来どおり0または1を受け付け、2011で同じ値を返す。 |
| `BSET-003` | 余白は既定指定、または開始・終了を両方持つ個別指定として受け付ける。片方だけの指定を作らない。 |
| `BSET-004` | 既定余白は開始5秒、終了2秒とし、2011では既定指定のまま返す。 |
| `BSET-005` | 個別余白は各-3,600～3,600秒とし、2011で同じ値を返す。 |
| `BSET-006` | 予定開始は番組開始－開始余白、予定終了は番組終了＋終了余白とする。結果は1秒～24時間に制限する。 |
| `BSET-007` | 無効予約は未完了一覧と重複防止に残し、録画処理とファイルを作らない。2015で再有効化できる。 |
| `BSET-008` | 予定終了を過ぎた無効予約は、一回のスケジューラ照合で最大一件を`FINISHED/DISABLED_EXPIRED`へ進める。 |
| `BSET-009` | 録画枠が空いた時、開始期限内の待機予約を優先度降順、予定開始昇順、内部ID昇順で選ぶ。実行中録画は入れ替えない。 |
| `BSET-010` | 開始前追従と録画中の終了延長は、同じ要求設定と実効余白を維持する。 |
| `BSET-011` | 旧DBの未完了予約は有効、既定余白指定、実効値5秒／2秒へ移行する。移行前バックアップを必須にする。 |
| `BSET-012` | 対象外の録画設定を無視せず、要求全体を変更しない失敗応答にする。 |
| `BSET-013` | 自動予約条件の録画モード1は有効予約、5は無効予約を作り、優先度、追従、既定／個別余白を引き継ぐ。 |
| `BSET-014` | 録画開始の5分猶予は予定開始から数え、録画できる残り時間が60秒未満なら開始期限切れとする。 |

## 受理するCtrlCmd録画設定

| 項目 | 受理する値 |
|---|---|
| `rec_mode` | 1、5 |
| `priority` | 1～5 |
| `tuijyuu_flag` | 0、1 |
| `service_mode` | 0 |
| `pittari_flag` | 0 |
| `bat_file_path` | 空文字列 |
| `rec_folder_list` | 0件 |
| `suspend_mode`／`reboot_flag` | 0／0 |
| `use_margin_flag` | 0、1 |
| `start_margin`／`end_margin` | flag 0ではwire値0、flag 1では各-3,600～3,600 |
| `continue_rec_flag`／`partial_rec_flag` | 0／0 |
| `tuner_id` | 0 |
| `partial_rec_folder` | 0件 |

表にない値や組合せは`recording-setting-out-of-profile`として失敗させる。成功に丸めたり、対応済みの項目だけを部分保存したりしない。

## 保存値

一件の予約は次を持つ。

- 有効値。
- 優先度と番組追従要求。
- 既定余白を使うかどうか。
- 実効開始・終了余白。

既定指定では、実効値を5秒と2秒にする。個別指定では、実効値を要求値としてそのまま2011へ返す。別の要求値列は作らない。DBから読んだ値がこの組合せに合わなければ、0秒へ丸めず破損として失敗する。

## 追加と変更

2013は番組照合後、設定を予約と同じトランザクションで保存する。2015は録画処理がない未完了予約だけを比較更新する。有効／無効、優先度、追従、余白は一度に置き換え、途中まで保存しない。

無効から有効へ変える時、予定終了を既に過ぎていれば失敗させる。予定開始を過ぎていても、既存の遅延開始上限と残り時間を満たす場合は有効化できる。有効から無効へ変えた後はスケジューラへ通知し、まだ確保していない録画を開始しない。

録画処理を確保した後の2015は、設定内容にかかわらず失敗させる。録画中の停止は1014だけを使う。

## 自動予約

検索条件自体の有効値は、その条件を評価するかどうかを表す。録画設定の`rec_mode=1`は有効予約、`rec_mode=5`は無効予約を作る。二つの有効値を混同しない。

作成する予約へ優先度、追従、既定／個別余白を引き継ぐ。個別余白の範囲と予定時間は、単発予約と同じ規則で検証する。対象外の録画設定を一つでも含む条件は、規則全体を利用不能として予約を作らない。対応項目だけを部分的に反映しない。

## スケジューラ

スケジューラは一回の照合で、次の順に処理する。

1. 予定終了を過ぎた無効予約を最大一件だけ終了させる。
2. 現在時刻までに予定開始を迎え、遅延開始上限内にある有効予約から、優先度が最も高い一件を選ぶ。
3. 同じ優先度なら予定開始が早い方、さらに同じなら内部IDが小さい方を選ぶ。
4. 開始済み録画が上限に達していれば、実行中録画を止めず、既存の待機または録画枠不足の処理を行う。
5. 開始期限内の予約がなければ、最も早い予定開始または無効予約の予定終了まで待つ。

固定の5秒先行起動は削除する。既定開始余白5秒が予定開始を番組開始より前にするため、既定動作の開始時期は維持される。

録画開始の5分猶予は予定開始から数える。予定終了までの残り時間が60秒未満なら、既存どおり`LATE_START_EXPIRED`とする。実効録画時間1秒という下限は保存値の構造を検証するものであり、残り60秒未満の録画開始を許可するものではない。

## 番組追従

録画開始前は、検証済み後継の番組開始と放送時間へ予約を更新する。余白の要求値と実効値は変えない。新しい予定開始と予定終了は録画処理の確保時に計算する。

録画中の終了延長では、現在の番組終了に実効終了余白を足した時刻が録画処理の予定終了と一致することを確認する。後継番組の終了に同じ余白を足した時刻が後ろで、既存の12時間上限内の場合だけ延長する。開始余白、開始時刻、短縮は録画中に変更しない。

## 終了状態

無効予約の予定終了は、録画処理を作らず予約だけを`FINISHED`へ進め、固定理由`DISABLED_EXPIRED`を保存する。録画履歴と完成録画一覧へは出さない。

有効予約の終了状態は既存仕様を維持する。余白を理由に正常完了、部分録画、失敗を別の状態へ丸めない。

## 固定上限

| 項目 | 値 |
|---|---:|
| 余白 | 各-3,600～3,600秒 |
| 実効録画時間 | 1秒～24時間 |
| 優先度 | 1～5 |
| 一回の無効予約終了 | 1件 |
| 同時録画 | 既定1、最大8件 |
| 予約一覧page | 256件 |
| 未完了予約 | 16,384件 |
| 追加goroutine／キュー | 0 |

## 必須テスト

### CtrlCmdと保存

- 固定KonomiTVの有効、無効、既定余白、個別余白のbyte列。
- 2013追加、2011読戻し、2015変更、無効化、再有効化。
- 優先度1と5、追従0と1、余白-3,600、0、3,600と一件超過。
- 片方だけの余白に相当する不正構造、対象外設定、truncated、一バイト超過。
- DB失敗、並行変更、録画確保との競合で部分保存しない。

### スケジューラと追従

- 既定5秒／2秒、明示0秒、正と負の余白による予定時刻。
- 予定時間1秒、24時間の境界と上下の一件超過、残り時間60秒の前後。
- 無効予約を開始しない、期限前に残す、期限後に一件ずつ終了する、再有効化する。
- 同時刻と異なる時刻の優先度順、同値の安定順、実行中録画を入れ替えない。
- 開始前追従と録画中延長へ終了余白を一度だけ加える。
- 最大8件、停止通知、再接続、process終了との競合。
- 自動予約条件の有効／無効、録画モード1／5、既定／個別余白から作る予約。

### DBと品質

- 旧DB migrationで未完了予約が有効、既定5秒／2秒になる。
- migration前backup、再起動、restore、旧版へのrollback。
- schema制約、破損値、未来schema、migration drift。
- full、shuffle、race、vet、`go mod verify`、`govulncheck`、CGO無効のLinux／Darwin amd64／arm64 build、Hosted Ubuntu CI。

### 実験環境

- KonomiTV v0.14.1で無効化、再有効化、優先度、既定余白、個別余白を保存して再表示する。
- 既定余白と個別余白で録画し、予定との差を秒数とbyte数だけで確認する。
- 番組情報、絶対path、接続先、生の要求と応答を記録しない。

## 対象外

- 優先度による実行中録画の停止。
- 保存先、ファイル名、字幕、データ放送、録画後動作、スクリプト。
- 全サービス、デコードなし、視聴、ぴったり録画、ワンセグ、連続録画、チューナー指定。
