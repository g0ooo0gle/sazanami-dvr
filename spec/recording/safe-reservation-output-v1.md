# 録画先フォルダー・ファイル名仕様 第1版

- Status: Accepted
- Accepted date: 2026-08-10
- Decision owner: Project owner
- Delegated reviewer: Codex
- Related decision: [`../../docs/adr/0041-safe-reservation-output-paths.md`](../../docs/adr/0041-safe-reservation-output-paths.md)
- Extends: [`basic-recording-settings-v1.md`](basic-recording-settings-v1.md)

## 目的

KonomiTV v0.14.1の予約画面から、一件の録画先フォルダーとファイル名テンプレートを指定し、録画保存ルート内の実ファイルへ欠落なく反映する。

## 要件

| ID | 要件 |
|---|---|
| `ROUT-001` | 2013と2015は、通常録画先0件、または対応形式の1件を受け付ける。 |
| `ROUT-002` | 録画先は録画保存ルートからの相対フォルダーとし、保存ルート外を表す値を拒否する。 |
| `ROUT-003` | 書き込みプラグインは`Write_Default.dll`、ファイル名プラグインは`RecName_Macro.dll`だけを受け付ける。 |
| `ROUT-004` | 対応マクロは予約の保存値だけから決定的に展開し、外部process、環境変数、現在ディレクトリを使わない。 |
| `ROUT-005` | 2011は保存したフォルダーとテンプレートを同じCtrlCmd形式で返す。テンプレートがある場合は実際の相対予定名も一件返す。 |
| `ROUT-006` | 録画処理の確保時に`FilePlan`を一度だけ作り、同じ処理の再接続、停止、追従で変更しない。 |
| `ROUT-007` | 同名の部分ファイルまたは完成ファイルがある場合は上書きせず、その録画だけを失敗させる。 |
| `ROUT-008` | 出力設定は予約の他の録画設定と同じtransactionで追加・変更し、失敗時に部分保存しない。 |
| `ROUT-009` | 自動予約条件の対応形式を作成予約へ引き継ぎ、対応外の条件から予約を作らない。 |
| `ROUT-010` | 旧DBの予約は空のフォルダーとテンプレートへ移行し、移行前backupから旧版へ戻せる。 |

## CtrlCmd入力

本仕様は、基本録画設定仕様の`rec_folder_list`を「0件」から次の範囲へ拡張する。`partial_rec_folder`は0件のままとする。これ以外の項目は基本録画設定仕様を変更しない。

`rec_folder_list`は0件または1件とする。1件の構造は次に固定する。

| 項目 | 受理する値 |
|---|---|
| `rec_folder` | 空、または後述の相対フォルダー |
| `write_plug_in` | `Write_Default.dll` |
| `rec_name_plug_in` | `RecName_Macro.dll`、または`RecName_Macro.dll?<template>` |
| reserved文字列 | 空 |

`rec_folder`と`<template>`が両方空の場合は、空vectorと同じ既定設定へ正規化する。2件以上、`partial_rec_folder`、別プラグイン、大文字・小文字違い、引数なしの`?`、reserved文字列は`recording-setting-out-of-profile`として要求全体を失敗させる。

基本録画設定仕様の他の項目は引き続き同じ制約を使う。保存先だけを成功させ、別の対象外設定を無視してはならない。

## 相対フォルダー

相対フォルダーはUTF-8で1～256バイト、`/`で区切った一つ以上の要素とする。各要素は空でなく、`.`と`..`ではない。先頭と末尾の`/`、連続する`/`、逆向き区切り、コロン、NUL、U+0000～U+001F、U+007Fを含めない。`path.Clean`の結果が入力と同じでなければ拒否する。

入力はhostの絶対pathへ変換せず、録画保存adapterへ渡す`FilePlan`の相対ディレクトリとしてだけ使う。ログ、JSON、互換表へ実際の入力値を出さない。

## ファイル名テンプレート

テンプレートはUTF-8で1～512バイトとする。`/`、逆向き区切り、NUL、U+0000～U+001F、U+007Fを含めない。`$`で始まる箇所は次の対応マクロと完全一致しなければならず、未知名、閉じていないマクロ、関数形式を拒否する。

### 対応マクロ

| 分類 | マクロ |
|---|---|
| 番組 | `$Title$`、`$Title2$`、`$ServiceName$` |
| 開始日時 | `$SDYYYY$`、`$SDYY$`、`$SDMM$`、`$SDM$`、`$SDDD$`、`$SDD$`、`$SDW$`、`$STHH$`、`$STH$`、`$STMM$`、`$STM$`、`$STSS$`、`$STS$` |
| 終了日時 | `$EDYYYY$`、`$EDYY$`、`$EDMM$`、`$EDM$`、`$EDDD$`、`$EDD$`、`$EDW$`、`$ETHH$`、`$ETH$`、`$ETMM$`、`$ETM$`、`$ETSS$`、`$ETS$` |
| 放送時間 | `$DUHH$`、`$DUH$`、`$DUMM$`、`$DUM$`、`$DUSS$`、`$DUS$` |
| 放送ID | `$ONID10$`、`$TSID10$`、`$SID10$`、`$EID10$`、`$ONID16$`、`$TSID16$`、`$SID16$`、`$EID16$` |
| 予約 | `$ReserveID$` |

日時は番組開始と終了をAsia/Tokyoへ変換して展開する。曜日は`日`、`月`、`火`、`水`、`木`、`金`、`土`の一文字とする。16進数は大文字4桁、予約番号は十進数とする。`$Title2$`は角括弧`[...]`で囲まれた部分を除く。それ以外の文字列はそのまま残す。

番組名、`$Title2$`、放送局名の展開値では、`/`、逆向き区切り、`<`、`>`、`:`、`"`、`|`、`?`、`*`、NUL、制御文字を`_`へ置き換え、CRとLFを除く。展開後は前後の空白と末尾の`.`を除き、末尾が大文字・小文字を区別せず`.ts`でなければ`.ts`を付ける。

完成名はUTF-8で1～240バイトの一要素とする。空、`.`、`..`、区切り、上限超過を拒否する。切り詰め、hash付加、連番化で別名へ変えない。

## ファイル計画

テンプレートが空の場合、完成名は従来どおり`<attempt-id>.ts`、部分名は`<attempt-id>.ts.partial`とする。フォルダーが空の場合のディレクトリは従来どおり番組開始UTCの`YYYY/MM`である。フォルダーを指定した場合は、その値をディレクトリとして使う。

テンプレートがある場合、完成名は展開結果、部分名は完成名に`.partial`を加えた値とする。フォルダーが空なら従来の`YYYY/MM`、指定があれば指定フォルダーへ置く。録画処理確保時の予約番号と番組情報から一度だけ展開し、`FilePlan`をDBへ保存する。

2011の`rec_file_name_list`はテンプレートがある予約だけ一件を返す。値はフォルダーを含む相対予定名とし、録画処理確保後は保存済み`FilePlan.FinalPath`と一致させる。確保前は同じ展開規則から算出する。既定名は録画処理IDが未確定なため空vectorを返す。

## DB

schema 9で`reservations`へ`output_folder`と`output_template`を追加する。両列はNULL不可、既定値は空文字列とする。長さと文字種の完全な検証はdomainで行い、DBは少なくともbyte長とNUL不在を制約する。

追加、変更、開始前追従、自動予約作成、読出しは二つの値を欠落なく扱う。開始前追従は番組情報だけを更新し、出力指定を変えない。録画処理確保後の2015は従来どおり失敗する。

## 自動予約

通常フォルダー0件、または同じCtrlCmd条件の1件だけを実行可能にする。ワンセグ分離先は0件に限る。自動予約評価はフォルダーとテンプレートを`Reservation`へ写し、単発予約と同じ検証を行う。

規則の変更前後で既に作った予約の出力指定は変えない。対応外のフォルダー、マクロ、プラグインを含む規則は利用不能として数え、対応部分だけで予約を作らない。

## 固定上限

| 項目 | 値 |
|---|---:|
| 通常録画先 | 0または1件 |
| 相対フォルダー | 256 UTF-8 bytes |
| テンプレート | 512 UTF-8 bytes |
| 展開後ファイル名 | 240 UTF-8 bytes |
| 部分・完成相対path | 既存の`FilePlan`上限以内 |
| 追加goroutine／queue | 0 |

## 必須テスト

### Domainとマクロ

- 空、フォルダーのみ、テンプレートのみ、両方の検証と`FilePlan`。
- 相対フォルダーの日本語、複数階層、256バイト、257バイト、絶対、親、現在、空要素、末尾区切り、逆向き区切り、コロン、NUL、制御文字。
- 対応マクロ全件、反復、混在、Asia/Tokyoの日付変更、終了時刻、曜日、16進大文字、予約番号。
- `$Title2$`とファイル名禁止文字の置換、`.ts`の有無、大文字拡張子、240バイト、241バイト。
- 未知マクロ、未閉鎖、関数形式、空展開、区切りを生成する入力を拒否する。

### CtrlCmdと自動予約

- 固定KonomiTV形式の0件／1件を2013、2015、2011でbyte単位に往復する。
- フォルダーとテンプレートを別々、同時、既定へ戻す。
- 2件、別write plugin、別name plugin、大文字違い、空引数、reserved、partial folder、truncated、末尾一バイト、本文上限。
- 失敗時、並行変更時、録画確保との競合で部分保存しない。
- 自動予約条件の0件／1件、作成予約への引継ぎ、規則変更後も既存予約を変えない、対象外規則を利用不能にする。

### DB、録画、品質

- schema 8から9へのbackup付きmigration、空の既定値、roundtrip、破損値、再起動、restore、未来schema、migration drift。
- 既定名、指定名、指定フォルダー、部分作成、完成、同名競合、停止、再接続、process終了、複数同時録画。
- 保存ルート外、symlink、完成済みファイルを上書きしない。
- full、shuffle、race、vet、`go mod verify`、`govulncheck`、CGO無効のLinux／Darwin amd64／arm64 build、Hosted Ubuntu CI。

### 実験環境

- KonomiTV v0.14.1相当の追加、2011読戻し、変更、既定へ戻す操作。
- 相対フォルダーと対応マクロを使う短い録画を公開Linux amd64配布物で完了する。
- 完成ファイルが録画保存ルート内の予定相対pathにあり、再生できることを件数、byte数、所要時間、終了理由だけで確認する。
- 絶対path、接続先、番組情報、ファイル名、生の要求・応答、TSを記録しない。

## 対象外

- 複数の通常録画先、ワンセグ分離、別write plugin。
- EDCBマクロ関数、28時間表記、ジャンル、サブタイトル、外部値に依存するマクロ。
- 絶対path、Windowsドライブ、共有pathの対応付け。
- 既存録画の移動と名前変更、連番による衝突回避。
- 字幕・データ放送の加工、録画後動作、スクリプト。
