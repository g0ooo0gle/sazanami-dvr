# 上限付き自動予約仕様 v1

- Status: Accepted
- Date: 2026-08-09
- Requirements: `BAR-001`～`BAR-012`
- Related ADR: ADR-0032

## 目的

KonomiTVとKomorebiが使うキーワード自動予約条件を永続化し、完成済み番組表から安全に将来番組を一度だけ予約する。

## 要件

### BAR-001: 対応操作

録画用CtrlCmd待受は2131の一覧、2132の追加、2134の変更、1033の削除を受け付ける。2131、2132、2134はCmd2 version 5、1033は従来形式とする。未対応command、版違い、不正な構造長、vector、末尾データは既存の安定した失敗へ変換する。

### BAR-002: 条件の読み書き

検索条件は、有効状態、検索語、除外語、大小文字、正規表現、タイトル限定、あいまい検索、ジャンル、サービス、曜日と時刻、映像形式、音声形式、除外指定、無料／有料、録画済みタイトル照合期間、番組長を保持する。録画設定は既存のKonomiTV予約と同じ全項目を保持する。追加、一覧、変更、再起動後の一覧で意味を変えない。

文字列はUTF-8換算4,096 bytes以下、サービス4,096件以下、ジャンル256件以下、日時64件以下、映像と音声各256件以下、録画フォルダ各16件以下とする。規則全体の永続化表現は256 KiB以下とする。

### BAR-003: 永続化と番号

SQLiteへ自動予約規則と規則・番組・予約の対応を保存する。CtrlCmd番号は正の32 bit整数を単調増加で割り当て、削除後に再利用しない。規則は最大128件とする。追加と変更は一つのtransactionで完了し、失敗時は以前の規則を維持する。

### BAR-004: 明示migration

DB形式を第5版へ進める。空DBは既存の明示migrationで作成できる。第4版DBは`db migrate`が検証済み事前backupを作った後だけ更新する。通常起動は`BEHIND`を拒否し、自動migrationしない。

### BAR-005: 評価時点

自動予約は、番組表同期、候補検証、完成世代の公開、番組時刻追従が成功した後に一回評価する。起動時の暗黙network接続、独立polling、自動再試行は追加しない。自動予約評価の失敗は別結果として出力し、すでに完成した番組表を失敗へ戻さない。

### BAR-006: 評価できる条件

番組名と説明への検索語、除外語、大小文字、Go標準libraryの正規表現、タイトル限定、サービス、Asia/Tokyoの曜日と時刻、番組長、無料／有料を評価する。空の検索語はほかの条件だけで評価する。複数の検索語は空白で区切ったAND、除外語は一語でも一致したら除外とする。

正規表現が不正な規則、あいまい検索、ジャンル、映像形式、音声形式、録画済みタイトル照合を要求する規則は、現在の番組表だけでは安全に判定できない。該当規則を保存と一覧の対象にはするが、予約を作らず安定した理由で集計する。除外指定も元の条件を判定できない場合は同様とする。

### BAR-007: 録画設定

自動作成する予約は、録画が有効、指定サービス録画、優先度1～5、保存先指定なし、batchなし、強制tunerなし、ワンセグ別出力なしである規則だけを対象にする。番組追従は規則の値を既存予約へ渡す。現在の録画処理が安全に適用できない設定を持つ規則は保存できるが、予約を作らず安定した理由で集計する。

### BAR-008: 重複防止

同じ番組インスタンスに有効または完了済みの予約がある場合、新しい予約を作らない。規則と番組の対応は再起動後も保持する。複数規則が同じ番組へ一致した場合はCtrlCmd番号が小さい規則を先に評価し、一件だけ作る。

取消済み予約は自動的に復活させない。同じ規則を削除して新しく作り直した場合も、同じ番組に予約履歴があれば新しい予約を作らない。

### BAR-009: 上限

一回の評価は規則128件、対象番組32,768件、比較4,194,304回、新規予約256件を超えない。番組の対象期間は現在時刻から八日後までとする。一件超過を事前に検出できる場合は予約作成前に停止する。実行中に上限へ達した場合は、それ以降を作らず既存結果を維持する。

### BAR-010: 失敗と再起動

規則一件の判定不能はほかの規則を停止しない。DB読出し、DB書込み、ID生成など正本を維持できない失敗は評価を停止する。予約作成と規則・番組対応の途中で停止した場合、再起動後は既存予約を照合して対応を補い、重複予約を作らない。

### BAR-011: 出力と互換表

成功時は評価規則数、対象番組数、一致数、新規予約数、重複数、判定不能規則数、所要時間だけを出力する。失敗時は安定した理由と所要時間だけを出力する。検索語、番組名、予約番号、接続先、絶対path、生の要求と応答を通常出力へ含めない。

公開互換表は1033を自動予約削除として修正し、KonomiTV API、KonomiTV同梱画面、Komorebiの操作、Sazanamiの保存、評価、実環境確認を別々に示す。

### BAR-012: 依存と境界

実装はGoだけを使い、新しい外部依存、Java、Node／npm、CGO、ORM、framework、code generationを追加しない。CtrlCmdの型はadapter内、評価規則はcore、処理順はapplication、SQLと永続化JSONはSQLite adapterへ置く。

## 必須テスト

- 4commandの正常系、空一覧、追加後一覧、変更、削除、再起動後読み戻し。
- version、body、structure、vector、文字列、個数、整数、末尾、一件超過、応答上限、cancel。
- すべての検索条件と録画設定のround trip。未知値は成功に丸めない。
- 文字列AND、除外、大小文字、正規表現、タイトル限定、サービス、日時、番組長、無料／有料。
- 不正正規表現、あいまい、ジャンル、映像、音声、録画済みタイトル条件、安全に適用できない録画設定。
- 同期二回、再起動、二規則一致、取消済み、完了済み、作成途中の照合、規則と番組と新規予約の各上限一件超過。
- 第4版DBのbackup付き移行、backup失敗時の不変、旧版拒否、integrity check、restore。
- `go test ./...`、shuffle、race、vet、`go mod verify`、`govulncheck ./...`、CGO無効のLinux／Darwin amd64／arm64 build、Hosted Ubuntu CI。

## 実環境確認

一時的な規則をKonomiTV v0.14.1のHTTP API相当または固定版CtrlCmd clientから追加する。実番組名を報告へ残さず、一件以上の将来番組が予約され、同じ同期を再実行しても増えず、変更、削除、再起動後の読出しが成功することを確認する。試験後は一時規則と不要な予約を削除し、元のdata rootを復旧する。
